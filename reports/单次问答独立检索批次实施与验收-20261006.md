# 单次问答独立检索小批次实施与验收

日期：2026-10-06。基于 `483fd46` 的本地未提交修改。

## 发布结论

代码实现及工程验证完成，批量执行暂不启用。真实三题配对诊断未通过现有质量门禁，且六次规划均只有一个初始检索步骤，未覆盖目标两步批量路径。因此不宣称真实问答已经提速，也不宣称质量没有回归。

真实 `.env` 未修改，仍为 `PRA_RESEARCH_AGENT_MODE=auto`；新增 `PRA_DIRECT_SEARCH_CONCURRENCY` 的默认值为 1。普通自动 RAG 可能绕过研究图。已有比较并发值 4 保持原配置。

## 已实现行为

- 非比较研究的完整独立查询可按最多两步并发执行，汇合后统一评估；旧计划默认单步。
- 查询范围去重、预算预扣、稳定顺序、共享证据字符预算、追问单步、失败与取消清理、checkpoint 原子提交和恢复均有边界检查。
- 研究图与最终运行时共用批次前缀校验；最终运行时继续核验原始证据与动作账目，不删除最终引用校验。
- 增加通用研究阶段耗时、检索批次与评估节点次数；评估节点次数不包含模型内部的重试尝试。
- 修复研究运行时复用已关闭异步 HTTP 连接的问题。每个研究运行时明确持有自己的异步连接，关闭和构造失败都释放资源。

## 测量口径

首次生产主 Agent 样本 GQ003 添加明确本地论文入口描述，走 local_rag 快路，主请求耗时约 13.24 秒，没有进入多轮研究图。初始化约 69.17 秒包含本地模型文件补齐，不能计入暖请求耗时。

下列真实配对在隔离评测进程中将研究模式设为 always，以覆盖研究图；没有写入生产 `.env`。使用现有 silver_generated 数据集的 GQ001、GQ003、GQ006，每题每配置一次。规划、评估和答案模型均正常调用，不给候选版本免除规划阶段。数据集、索引和模型保持相同；模型生成与模型裁判仍有方差。

gold runner 的 latency_ms 包含裁判请求，因此以下时间只是评测运行耗时，不是网页问答完成时间。两组都生成单步计划，参数 2 未实际产生双步批次。

## 受控延迟对照

固定四个独立查询、相同工具结果、每次搜索 40 毫秒延迟和每次评估 80 毫秒延迟；串行与两步批次交替运行三组。

| 指标 | 单步 | 两步批次 |
| --- | ---: | ---: |
| 完成时间中位数 | 564.84 ms | 284.40 ms |
| 模型评估次数 | 4 | 2 |
| 工具调用次数 | 8 | 8 |
| 最终证据数量 | 4 | 4 |

受控场景缩短 49.65%；六次证据哈希完全一致。这验证了调度收益和证据集合一致性，不代表真实 Provider 的收益，更不等同于真实答案质量验收。

## 启用条件与回滚

仍需有实际产生两个独立步骤的同题配对样本、人工可复核的必要事实和引用检查，并通过既有质量门禁。满足之前保持默认 1，不降低门禁阈值。

未来验收通过后可在现有运行配置中设 `PRA_DIRECT_SEARCH_CONCURRENCY=2` 并重启本地服务。恢复为 1 即回滚调度；不删除会话、checkpoint 或论文数据。没有部署外部服务，没有创建 Git 提交。

执行规则见 `docs/单次问答独立检索批次.md`。安全测量输出仅保存在本地被忽略的 `data/evaluations/runs/`；报告不包含问题、证据、答案正文或凭据。
