# 事实查询语义锚点与执行门控修复 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在固定 Top 4、现有重排器和现有 RAG query rewrite 不变的前提下，以结构化语义锚点和确定性查询组合消除 Planner 的破坏性改写，并保证每个新规划事实的原子查询在 Compiler 判断充分前真实执行。

**Architecture:** 将新规划事实的自由 `search_query` 拆为必须逐字来自用户问题的 `protected_anchors` 与只允许增加信息的 `retrieval_expansions`，由本地代码结合论文名确定性组合最终查询；旧 `search_query` 只保留为 checkpoint 兼容字段。研究图把满足新契约的 comparison 单元步骤确定性展开为事实级初始步骤，全部完成后才进行第一次事实编译，同时在 assessment 校验层拒绝“仍有结构化事实查询未执行但已判充分”的状态。

**Tech Stack:** Python 3.12、Pydantic v2、LangGraph、pytest、Ruff、mypy、现有私有固定 Top 4 端到端评测。

---

## 不变量

- 固定每次水化 Top 4，自适应水化继续关闭。
- 不修改当前 retriever、reranker、候选池、融合参数或 RAG query rewrite。
- 不增加 Planner、Compiler、回答生成或评测裁判的模型调用次数。
- 不使用金标、论文正文或目标 chunk 生成生产查询。
- 不修改主图与 RAG 子图的交接。
- 保留旧 checkpoint：缺少新字段的旧事实仍能反序列化并沿用旧步骤；只有新 Planner 输出必须满足新契约。
- 不回滚或覆盖工作区现有未提交改动，不提交、不推送。

**Step 3: 修改提示词和结果校验**

提示词明确使用 augment（增强）而非 rewrite（改写）：

- `protected_anchors` 只能复制用户问题中的最短有意义原文片段。
