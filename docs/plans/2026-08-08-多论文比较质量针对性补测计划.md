# 多论文比较质量针对性补测 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 用最小、可重复的测试确认多论文比较在上下文预算受限时是否公平保留各目标论文证据，并复用历史同题切片评估真实质量。

**Architecture:** 先在 `Context Assembler` 边界构造两篇论文、多个按发现顺序排列的证据，验证 comparison task state 能否让最终上下文覆盖两个 target。门禁确认缺陷后，comparison 模式根据 task state 中的 target 与 requirement coverage 对候选证据做公平排序；普通任务继续保持全局 rank 顺序。修复通过后，再以历史固定 5 题进行真实模型对照，最后才扩到全部多论文切片。

**Tech Stack:** Python、Pydantic v2、pytest、现有 RAG Gold runner、BM25＋FAISS 混合检索。

### Task 3: 分阶段真实质量重测

**Files:**
- Output: `data/evaluations/runs/rag-comparison-fixed-scope-sample5.json`
- Output: `reports/RAG多论文固定范围-sample5.md`

**Step 1: 单题 smoke**

优先回放历史结构失败题 GQ017，确认固定图能完成规划、范围检索和回答。

**Step 2: 固定 5 题对照**

使用历史相同问题顺序，报告运行成功率、状态准确率、Claim/Citation F1、Span Recall、Required Group Recall、Paper Recall 和 P50/P95。

**Step 3: 判断是否扩量**

只有运行成功率 100%、Paper Recall ≥70%、Span Recall ≥18.2%、P50 <45 秒时，才扩到 10 条可回答题和 2 条不可回答近邻负例；否则先修复 coverage-aware evidence selection。

### Task 4: 最终回归策略

**Files:**

### Task 5: 修复 comparison 上下文证据公平性

**Files:**
- Modify: `src/paper_research_agent/context/assembler.py`
- Modify: `tests/context/test_assembler.py`

**Step 1: 将严格 xfail 转为正式失败门禁**

移除预期失败标记，保留预算恰好容纳两条证据时必须同时包含两个 target corpus 的断言。

**Step 2: 解析比较证据优先级**

安全解析 task state 的 comparison plan、targets、requirements、observations 和最终 assessment coverage。按 target 轮转 requirement chunk；缺少完整 coverage 时至少按 target corpus 轮转候选证据。

**Step 3: 保留普通问答排序不变量**

非 comparison、非法 task state 或没有有效 target 时继续使用 `(final_rank, chunk_id)` 顺序，不改变直接问答行为。
