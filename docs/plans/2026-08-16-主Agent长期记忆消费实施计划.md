# 主 Agent 长期记忆消费 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让主 Agent 在每轮解释前安全召回长期记忆、让模型能够看到并选择相关记忆，并确保被选择的记忆在 direct chat、local RAG 和 dynamic tools 三条执行路径中得到有界消费，同时保持长期记忆不可充当论文证据、写入仍需明确意图和用户审批。

**Architecture:** 复用现有 `manage_long_term_memory(action="search")` 作为唯一读取来源，新增一个只读 Provider 适配器并注入现有 `ContextHydrator`，不新增第二套数据库或平行 LangGraph 节点。解释器接收带 ID、类型、信任级别和正文的有界上下文，并通过 `selected_context_ids` 决定哪些远距历史或长期记忆可以进入子任务；RAG 上下文新增独立的低信任长期记忆层，和 citation evidence（引用证据）严格隔离。

**Tech Stack:** Python 3.11+、Pydantic v2、LangGraph、LangChain、FastAPI、SQLite、pytest/unittest。

---

## 边界与完成标准

本计划只解决长期记忆的读取和消费，不改变已有写入安全策略：

- `add/update/delete` 仍只允许显式记忆意图触发，并继续要求一次性审批令牌。
- `search/list` 仍为只读，不请求审批。
- `confirmed_conclusion` 仍必须绑定当前可用的 citation chunk ID。
- 长期记忆始终标记为低信任 `research_context`，不得生成论文引用，不得替代本轮检索证据。
- 没有长期记忆运行时、数据库不可用、查询失败时必须降级为空，不阻断普通聊天和 RAG。
- 不记录记忆正文、用户问题或 Provider 原始载荷到事件日志。

完成后必须满足：

1. 生产 bootstrap 确实给 `ContextHydrator` 注入长期记忆 Provider。
2. `ContextHydrator` 在路由前最多召回 5 条长期记忆，并遵守现有 5,000 字符预算。
3. 解释器提示词包含有界上下文正文，而不是只有 ID。
4. 只有 `selected_context_ids` 选中的远距历史和长期记忆进入 `ChildTaskRequest.selected_context`。
5. direct chat、local RAG、dynamic tools 都能消费选中的长期记忆。
6. local RAG 的引用校验只接受本轮 evidence chunk，不接受长期记忆 ID。
7. 读取失败可观测但不泄露正文，并且不影响主请求完成。

**Step 3: 实现最小只读适配器**

在 `src/paper_research_agent/agent/orchestrator/memory.py` 中定义窄 Protocol 和实现：

```python
class LongTermMemoryToolExecutor(Protocol):
    async def execute_tool(
        self,
        tool_name: str,
        arguments: dict[str, Any],
        *,
        run_id: str | None = None,
    ) -> object: ...


class ToolkitLongTermMemoryProvider:
    def __init__(
        self,
        executor: LongTermMemoryToolExecutor,
        *,
        scope_id: str = "global",
    ) -> None:
        self._executor = executor
        self._scope_id = scope_id

    async def search(
        self,
        query: str,
        *,
        limit: int = 5,
    ) -> tuple[dict[str, object], ...]:
        result = ToolExecutionResult.model_validate(
            await self._executor.execute_tool(
                "manage_long_term_memory",
                {
                    "action": "search",
                    "scope_id": self._scope_id,
                    "query": query[:500],
                    "limit": limit,
                },
            )
        )
        if result.status not in {"ok", "not_found"}:
            raise RuntimeError("long-term memory search returned an invalid status")
        return tuple(dict(item) for item in result.items)
```

不要直接连接 SQLite；复用工具层可以继承过期过滤、scope、状态过滤和后续检索升级。
