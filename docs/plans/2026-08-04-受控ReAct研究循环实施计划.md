# 受控 ReAct 研究循环 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将固定的 Plan-and-Execute 研究图升级为可根据证据充分性动态结束或改写检索的受控 ReAct 循环。

**Architecture:** 保留现有 `search_corpus` 与 `get_evidence` 两个只读领域工具，并通过 LangChain `StructuredTool` 实际执行。LangGraph 负责 `plan → reason → act → observe → assess` 条件循环；模型只生成结构化计划和证据评估，Runtime 继续强制工具白名单、调用预算、总超时、检查点隔离和不可变证据复验。

**Tech Stack:** Python 3.11+、Pydantic v2、LangChain、LangGraph、SQLite Checkpointer、unittest

### Task 3: 将研究图升级为受控 ReAct

**Files:**
- Modify: `src/paper_research_agent/agent/graph.py`
- Modify: `tests/agent/test_graph.py`

**Step 1: Write the failing tests**

覆盖以下图行为：

- 第一轮证据充分时提前结束，不执行剩余计划。
- 证据不足时用评估器建议替换下一检索并增加 `replan_count`。
- 重复查询被拒绝并有界终止。
- 每个工具执行前都消费 Runtime policy 预算。
- `search_corpus` 无命中时不调用 `get_evidence`。
- 完成状态可由 LangGraph checkpointer 恢复。

**Step 2: Run tests to verify they fail**

Run: `.venv/Scripts/python.exe -m unittest tests.agent.test_graph -v`

Expected: FAIL，因为当前图仍是固定循环。

**Step 3: Write minimal implementation**

图节点改为：

`START → plan → reason → execute_tools → assess_evidence → reason → finalize → END`

要求：

- `reason` 只选择下一步或终止，不直接执行工具。
- `execute_tools` 通过 `build_langchain_tools` 返回的 LangChain 工具调用现有 Service。
- 所有动作追加到无证据正文的 `action_history`。
- `current_step`、`replan_count`、`next_action`、`evidence_sufficient`、`termination_reason` 写入 State。
- 计划步数、工具次数和重复查询全部有硬上限。

**Step 4: Run tests to verify they pass**

Run: `.venv/Scripts/python.exe -m unittest tests.agent.test_graph -v`

Expected: PASS。
