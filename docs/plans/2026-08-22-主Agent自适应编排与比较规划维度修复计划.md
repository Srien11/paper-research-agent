# 主 Agent 自适应编排与比较规划维度修复 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 修复比较研究反复出现的 `planner_dimension_invalid` 终止错误，并把主 Agent 从固定三段模型规划改为保守的自适应编排，使明确的单一 `local_rag` 请求近乎无感地进入研究子图，同时完整保留复杂任务的规划、安全、审批、恢复与提交语义。

**Architecture:** 比较研究中，本地代码从 `comparison_dimension_hints` 物化固定维度骨架并拥有维度数量、顺序、ID、完整网格、预算和引用契约；Provider（模型服务）只选择候选论文并为已给定的零基维度索引提出原子事实意图，提案修复失败时使用问题原文生成安全、确定性的事实骨架。主 Agent 在上下文水化后先执行一个无模型、保守 allowlist（允许清单）分类器：只有全新、无附件、明确属于单一私有论文问答/比较的请求才构造一个 `local_rag` 任务并复用既有路由、执行、评估和提交链，其余请求继续经过 `TurnInterpreter → GoalReconciler → TaskPlanner`。

**Tech Stack:** Python 3.12、asyncio、LangGraph、Pydantic v2、LangChain structured output、本地 SQLite 安全审计、pytest、Ruff、mypy、现有生产主图单题冒烟与固定 Top 4 五题门禁。

### 3. 根因边界

这不是候选论文解析失败：

- `LangChainComparisonTargetResolver.resolve()` 已经成功得到候选集。
- CPG020 的 `comparison_dimension_hints()` 确定性返回恰好 3 个提示。
- 当前 `ComparisonPlanProposal` 仍让模型返回 `dimension_labels`；模型必须在最多两次串行尝试中返回恰好 3 个非空、唯一、顺序一致的标签，并为每个零基 `dimension_index` 提交事实。
- 最终模型输出仍违反维度契约，因此 `_planner_failure_code()` 产生 `planner_dimension_invalid`。
- `LangChainResearchPlanner.plan()` 把所有 mandatory comparison（强制比较规划）失败统一包装为 `ComparisonTargetResolutionError`，造成错误分类误导。
- 原始问题和模型输出按设计不持久化，因此现有审计只能确认安全失败码，不能区分“数量错误、空标签、重复标签”中的哪一种；本计划继续保持不存正文。

主 Agent 的固定延迟来自全新单任务也串行执行三个模型阶段：

1. `TurnInterpreter.interpret`
2. `GoalReconciler.reconcile`
3. `TaskPlanner.plan`

正确修复不是取消主 Agent 的规划能力，而是把规划升级为按复杂度启用：确定性结构由代码负责，只有语义上不可约的决策才交给模型。

## 二、设计不变量与发布门禁

### 1. 比较研究不变量

- Top 4、六路检索、完整 target×dimension 网格、事实原子性、Compiler 校验和确定性答案渲染不变。
- 维度数量、顺序、稳定 ID、网格、step 预算、fact 预算、corpus scope 和 citation contract（引用契约）只由本地代码控制。
- Provider 不再选择、删除、合并、增加或重排维度；它只返回合法候选 corpus ID 和绑定既有 `dimension_index` 的事实意图。
- Provider 最多尝试 2 次；不得为了提高成功率增加串行重试。
- 事实提案修复失败时，只能使用来自当前问题和 `comparison_dimension_hints()` 的确定性 fallback（回退）；不得读取金标、论文正文、答案或私有参考结论来补计划。
- 目标解析真正失败仍 fail closed；不得从不足或越界候选中猜测论文。
- 任何审计只允许固定枚举、安全码、次数、耗时、计数和哈希；不得保存问题、模型输出、query、事实、答案或论文正文。

### 2. 主 Agent 快路不变量

- 快路是保守 allowlist，默认不确定即进入 `full_planner`。
- 快路只创建一个 `local_rag` 任务；不能选择 `dynamic_tools`、`attachment_qa`、`file_edit` 或任何任意工具。
- 快路继续复用现有 `select_next_task → route_task → dispatch_child → evaluate_result → update_task_state → validate_commit → commit_turn`；不得绕过预算、审批、评估、幂等、checkpoint 或提交校验。
- 以下请求必须进入完整规划：多任务、跨 capability（能力）、依赖关系、附件与研究组合、文件修改、动态工具或最新网页信息、敏感审批、澄清、已有活动目标的跟进/修订/取消、resume（恢复）、缺少必要上下文以及分类器无法证明为单一私有论文请求的情况。
- `PRA_MAIN_AGENT_FAST_PATH_ENABLED=false` 必须能立即恢复原完整主 Agent 路径；回滚快路时不得回滚六路检索和确定性答案。

### 3. 性能门禁

- 快路主编排前奏目标低于 500 ms；硬上限 1 秒。不把 Runtime 冷加载计入该指标。
- CPG020 三次全新会话不得再出现 `planner_dimension_invalid`。
- 三次单题 p50 目标低于 50–55 秒；若外部 Provider 方差导致绝对门禁未达标，仍必须分别证明快路为零主 Agent Provider 调用、维度错误消失、六路 search 单批、答案 Provider 为零。
- 单题门禁通过后才运行固定 Top 4 五题；五题通过前不得运行全量 30 题。

```python
class ComparisonPlanningError(RuntimeError):
    """Resolved comparison candidates could not be materialized into a safe plan."""

    def __init__(
        self,
        reason_code: str,
        *,
        attempts: tuple[PlannerAttemptAudit, ...] = (),
    ) -> None:
        self.reason_code = reason_code
        self.attempts = attempts
        super().__init__(f"comparison planning failed: {reason_code}")
```
