# 证据台账约束生成 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 把已经召回的比较证据编译为逐论文、逐维度、逐事实可追踪的证据台账，并让最终答案只能消费台账事实，以提高必要事实召回率和答案完整率。

**Architecture:** 保留现有候选发现、论文语料硬隔离、原子检索、批量补检和冻结预算；升级现有 `assess_evidence` 模型调用，使其同时输出覆盖结论、原子事实和补检计划，不增加正常检索路径的模型调用。比较回答改为“按维度选择台账事实 → 确定性合并与校验 → 仅修补失败维度”，生产链不读取私有金标，金标只在离线评测阶段做分段归因。

**Tech Stack:** Python 3.11+、Pydantic v2、LangGraph、现有 DashScope 结构化输出、pytest、Ruff。

---

## 设计不变量

- `EvidenceAssessment` 是证据台账的唯一生产入口；不另加一次证据编译模型调用。
- 每个台账单元格严格对应一个 `requirement_id`，由计划确定其论文和维度。
- 每条事实必须引用至少一个真实、已水合且属于该单元格的 `chunk_id`。
- 比较生成器看不到原始证据块，只看到原问题、比较计划、该维度的台账事实和可信引用编号。
- 合并器只能选择、排序已有事实或维度草稿，不接收可新增事实的自由文本字段。
- 私有参考答案、必要事实和评分金标只进入 `evaluation` 评分器，不进入 `agent`、`context`、`answering` 或 `web` 生产对象。
- 本计划基于当前未提交的动态预算改动增量实施；不执行 `git reset`、`checkout`、`commit`，不覆盖现有工作区修改。
