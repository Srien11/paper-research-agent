# RAG 与联网研究并行双任务 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将 `preferred` 模式下需要本地论文证据与外部学术信息的请求，确定性地规划为 `local_rag` 和 `dynamic_tools` 两个只读证据任务，在同一并行批次中同时启动、独立执行、汇合后由仍可使用自身知识的大模型综合回答。

**Architecture:** 主 Agent 不再用单一 `route` 表达混合研究，而是把任务计划中的同组 `local_rag` 与 `dynamic_tools` 识别为一个 `ParallelTaskBatch`（并行任务批次）。批次由 `asyncio.TaskGroup`（结构化并发）同时调度两个既有子图；每个分支捕获自身异常和超时，主图在 join（汇合）节点按确定顺序一次性归并任务状态、预算、事件与来源，再进入现有大模型综合器。这两个并行任务只是证据获取分支；大模型仍负责规划、推理、概念背景补充和最终综合，不需要再创建第三个 `direct_chat` 子任务。

**Tech Stack:** Python 3.11、FastAPI、Pydantic、LangGraph、`asyncio.TaskGroup`、SQLite/aiosqlite、原生 JavaScript、pytest。

---

## 1. 结论与当前边界

可以实现，而且不需要把本地 RAG 图与动态工具图合并成一张大图。两个子图已经使用独立的 task ID 和 checkpoint thread ID，适合在主 Agent 层并行协调。

当前实现尚不具备以下能力：

1. 主图一次只选择一个 `active_task_id`，执行路径是 `select_next_task -> route_task -> dispatch_child -> evaluate_result`，因此混合任务只能顺序执行。
2. `preferred` 的组合语义只存在于提示词和文档中，没有计划级确定性门禁。
3. “联网、网上、外部资料”等表达会漏过快路拒绝规则，可能被直接构造成单一 `local_rag`。
4. 动态工具目前允许写工具和审批；并行联网分支必须收窄为只读 `network_read`，不能在 RAG 执行期间产生副作用。
5. 学术 Provider（提供方）当前默认 `offline`；并行调度完成后，真实联网仍需要显式启用 `live` Provider。第一版只覆盖现有 Semantic Scholar/Crossref 学术网络能力，不新增通用网页抓取或搜索引擎。

## 2. 已选方案与实施前确认项

### 2.1 推荐方案

- 入口不新增按钮：继续使用现有请求字段 `rag_mode`。
- `disabled`：禁止本地 RAG；外部研究按单任务执行。
- `required`：只允许本地 RAG；禁止外部研究。
- `preferred`：
  - 纯寒暄不触发研究；
  - 本地论文问题只执行 `local_rag`；
  - 只要任务需要外部资料，就确定性地形成 `local_rag + dynamic_tools` 并行双任务；
  - 模型漏掉任一分支时由服务端策略补齐，不能静默退化为二选一。
- 并行双任务只允许 `local_rag` 与只读 `dynamic_tools`；附件、文件编辑、写工具和审批不进入该并行组。
- `direct_chat` 不是混合研究的第三个并行分支。大模型的自身知识通过 planner、两个子图内的模型节点以及最终 synthesizer 持续可用，关闭 RAG 从来不等于关闭大模型。
- 联网分支同时受风险级别和工具名单双重白名单约束；首版只能调用现有四个学术元数据工具，不能因其他工具同属 `network_read` 就获得访问权。
- 两个初始分支必须在同一批次启动，不能把 `dynamic_tools` 设为依赖 `local_rag`。
- 不存在“把并行组拆成两个单任务顺序跑”的降级路径；并行功能开关关闭时，混合请求在任何子图启动前 fail closed（安全拒绝）。
- 完成顺序可以不同，但持久化、综合与来源展示固定按 `local_rag`、`dynamic_tools` 排序，保证结果可重复。

### 2.2 技术选择

选择：在主图增加显式 `ParallelTaskBatch`，使用 `asyncio.TaskGroup` 并行执行。

原因：

- 不改变两个子图内部状态机和证据边界；
- 主图 checkpoint 仍把一次批次视为一个原子节点；
- 容易实现“一个分支失败不取消另一个分支”；
- 容易统一计算批次预算、事件和降级状态；
- 现有单任务路径可以作为 size=1 的批次继续复用。

可行替代方案：使用 LangGraph `Send` 做动态 fan-out（扇出）。该方案适合未来扩展到三个以上同构研究分支，但首版需要为多个并发 state update 增加 reducer、解决 checkpoint 写入顺序和产品事件去重，改造面明显更大，本次不选。

### 2.3 默认失败与降级语义

| 本地 RAG | 联网研究 | 运行结果 | 用户可见行为 |
| --- | --- | --- | --- |
| 成功 | 成功 | `completed`，非降级 | 大模型结合自身知识解释概念与推导关系，分别展示本地证据和外部学术信息，再给综合结论 |
| 成功 | 失败/超时/Provider 离线 | `completed`，`degraded=true` | 保留本地可引用答案与模型背景解释，明确说明外部核验未完成 |
| 失败/证据不足 | 成功 | `completed`，`degraded=true` | 展示外部学术信息与模型背景解释，明确说明没有本地论文证据支持 |
| 失败 | 失败 | `completed`，`degraded=true` | 仍可返回大模型背景回答，但必须显著标记“未经本地或外部证据核验”，不生成任何引用，不声称最新状态已获验证 |
| 任一分支请求写操作/审批 | 该分支失败 | 另一分支继续 | 返回 `parallel_write_not_allowed`，不发生副作用 |

初始两分支必须并行。若其中一个分支后续需要重试，只重试失败分支，不重复已经成功的分支；这不改变首轮并行不变量。

### 2.4 暂停、取消与一致性

- 浏览器断开继续沿用现有共享业务运行，不取消后台任务。
- `pause`（暂停）在并行批次结束后生效；UI 显示“当前并行批次完成后暂停”，避免无法安全恢复的半节点 checkpoint。
- `cancel`（取消）与暂停一样在当前并行批次汇合后生效；批次不做部分 workspace 提交，后续开放任务统一转为取消。
- 两个结果在 join 后一次性更新 `workspace_draft`，不允许一个任务先提交、另一个任务后提交。
- 每个分支保留独立 task ID、thread ID、预算和来源；禁止跨分支挪用引用。

### 2.5 已确认与生产启用边界

用户已确认：

1. 目标是增加外部学术检索证据；首版复用 Semantic Scholar/Crossref，不把大模型直接回答误当成网页搜索。
2. 启用本地 RAG 和外部学术检索时，不禁用大模型自身知识；模型仍负责规划、推理、背景解释与最终综合。

本次实现采用并已通过离线测试与界面验收：

1. 一个分支失败时返回带明确标记的部分结果；两个证据分支都失败时返回无引用的大模型背景答案。
2. 暂停和取消都在当前并行批次汇合后生效，避免产生半提交 workspace。

尚未获得的权限仅限生产 live 启用：部署时显式设置 `PRA_SCHOLARLY_MODE=live` 并执行真实
Provider 冒烟仍需管理员联网授权；API Key 只允许保存在本机环境中。

### 2.6 大模型自身知识的使用边界

- RAG 开关只控制本地检索，不控制大模型是否可以回答、推理或补充通用背景。
- 并行批次始终只有两个证据任务：`local_rag` 和 `dynamic_tools`。不为“模型自身知识”另起 `direct_chat` 任务，避免重复调用与三路状态膨胀。
- synthesizer 可以使用模型已有知识做概念解释、归纳、对比和推论；这些内容的 `source_ids` 必须为空，不能冒充本地论文或外部 Provider 证据。
- 关于“最新、当前、已发布、仍维护、已撤稿”等时效性事实，没有外部学术证据时必须表述为“未核验”，不能仅凭模型记忆下结论。
- 本地论文的具体引文、页码、实验数字和作者原意必须由 `LocalRAGArtifact` 支持；模型记忆不能补造本地引用。
- 两个证据分支都不可用时，允许输出无引用的模型背景答案，但结果必须是 `degraded=true`，并附带 `model_background_only` 降级码。

## 3. 目标执行流

```text
interpret / plan
  -> enforce capability policy
  -> select next batch
       -> size=1: 原单任务
       -> size=2: local_rag + dynamic_tools
  -> preflight budget + provider + read-only policy
  -> parallel_group_started
       +-> TaskGroup: local_rag child ----------------+
       +-> TaskGroup: dynamic_tools child ------------+
  -> join results in deterministic order
  -> evaluate both
  -> atomic workspace reduction
  -> parallel_group_completed
  -> retry failed branch only / select next batch / synthesize
```

## 4. 数据契约

### 4.1 `AgentTask` 新字段

```python
parallel_group_id: str | None = Field(
    default=None,
    pattern=r"^[A-Za-z0-9_-]{1,64}$",
)
allowed_tool_risks: tuple[
    Literal["local_read", "network_read", "restricted_compute", "write"], ...
] = ()
allowed_tool_names: tuple[str, ...] = ()
```

首版学术联网工具名单固定为：

```python
SCHOLARLY_NETWORK_TOOL_NAMES = (
    "search_scholarly_sources",
    "resolve_paper_identifier",
    "get_citation_graph",
    "check_paper_status",
)
```

并行组不变量：

- 同一 `parallel_group_id` 首版恰好两个任务；
- capability 集合必须严格等于 `{"local_rag", "dynamic_tools"}`；
- 两任务不能相互依赖；
- 两任务必须拥有相同的外部依赖集合；
- `dynamic_tools.allowed_tool_risks == ("network_read",)`；
- `dynamic_tools.allowed_tool_names == SCHOLARLY_NETWORK_TOOL_NAMES`，且名称不允许重复；
- `local_rag.allowed_tool_risks` 为空；
- `local_rag.allowed_tool_names` 为空；
- `required` 和 `disabled` 模式不能产生并行组。

### 4.2 批次模型

在新文件 `src/paper_research_agent/agent/orchestrator/parallel.py` 定义：

```python
class TaskBatch(FrozenModel):
    batch_id: str
    task_ids: tuple[str, ...] = Field(min_length=1, max_length=2)
    execution_mode: Literal["single", "parallel"]


class BatchDispatchResult(FrozenModel):
    batch: TaskBatch
    results: tuple[ChildTaskResult, ...]
    elapsed_seconds: float = Field(ge=0)
```

结果顺序固定为：

1. `local_rag`
2. `dynamic_tools`

单任务批次保持原任务顺序。

### 4.3 主结果降级字段

```python
degraded: bool = False
degradation_codes: tuple[str, ...] = ()
```

允许的首版 code：

- `local_evidence_insufficient`
- `external_research_unavailable`
- `external_research_timeout`
- `parallel_write_not_allowed`
- `model_background_only`

## 5. 验收标准

1. 输入“结合本地论文 C001 和联网搜索核验最新状态”，`rag_mode=preferred` 时，计划中必须出现同一 `parallel_group_id` 的两个任务。
2. 两个 fake executor 各等待 200 ms 时，端到端 wall time 应小于 320 ms，且两者都在任一方完成前进入 started 状态。
3. `route_trace` 固定为 `("local_rag", "dynamic_tools")`，不随完成先后变化。
4. 两个 `task_started` 事件先于任意对应 `task_completed/task_failed`；所有 event ID 唯一且严格递增。
5. 一个分支超时时，另一个分支不被取消，成功结果进入最终回答。
6. 并行动态分支只能执行四个学术元数据工具；`write`、`restricted_compute`、`local_read` 以及白名单外的 `network_read` 工具全部必须在执行前被拒绝。
7. `required` 永远不会创建或执行动态分支；`disabled` 永远不会创建本地分支。
8. planner 模型异常、非法 JSON、依赖环或漏任务时，显式混合请求仍由确定性 fallback 生成并行双任务。
9. SQLite workspace 只发生一次版本递增；进程在 join 前失败时不留下半完成主 workspace。
10. 本地引用只来自 `LocalRAGArtifact`；外部来源不能伪装为 `citation_evidence`。
11. 现有单任务、审批恢复、附件、文件编辑、暂停、取消和幂等测试全部通过。
12. 真实 Provider smoke test 能证明 `network_accessed=true`；离线模式必须明确返回 Provider 不可用，不能假装已联网。
13. `PRA_PARALLEL_HYBRID_RESEARCH_ENABLED=false` 时，混合请求在两个 executor 启动前返回 `parallel_hybrid_disabled`；不允许串行执行，也不允许静默只选一支。
14. 混合请求的 child task 集合严格等于 `{"local_rag", "dynamic_tools"}`，不创建 `direct_chat` 第三分支；最终 synthesizer 仍必须调用大模型。
15. 测试综合器可以输出 child artifact 中没有逐字出现的通用概念解释，但该内容不能获得本地或外部 `source_id`；无外部证据的时效性断言必须显示“未核验”。
16. 两个证据分支都失败时，只要 synthesizer 可用，仍返回 `completed` 且 `degraded=true`、`model_background_only`、无引用的背景答案；只有大模型综合也不可用时才把 run 置为 `failed`。

## 6. 不在本次范围

- 不新增通用搜索引擎、网页抓取器或浏览器工具。
- 不将外部论文自动下载、解析并写入本地知识库。
- 不允许联网结果直接成为本地论文引用。
- 不并行执行写操作、附件修改或需要审批的任务。
- 不支持三个以上能力同时 fan-out。
- 不修改论文 PDF、向量索引、运行数据库或数据版权边界。

async def _run_one(request, timeout_seconds):
    started = time.perf_counter()

        if timeout_seconds is None:
            result = await dispatcher.dispatch(request)
        else:
            async with asyncio.timeout(timeout_seconds):
                result = await dispatcher.dispatch(request)
    except asyncio.CancelledError:
        raise
    except TimeoutError:
        result = _timeout_result(request)
    except Exception as exc:

    return result, time.perf_counter() - started
