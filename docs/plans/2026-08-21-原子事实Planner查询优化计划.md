# 原子事实 Planner 查询优化 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在固定 Top 4、保留当前重排器且自适应 Top K 默认禁用的条件下，让研究 Planner 为每个原子事实意图生成独立、可检索、可追踪的查询，并把既有 8 条真实水化缺失降至不超过 2 条。

**Architecture:** 保留“论文 × 维度”初始发现步骤和现有 RAG 双语查询改写，只在 Planner 契约中为每个 `EvidenceFactRequirement` 增加独立的 `search_query`，事实编译确认缺口后按一个事实一个查询执行确定性 follow-up。主图与研究子图之间的信息压缩是已确认的独立问题，本计划只记录、不修改；不得把主图交接改造、Top K 扩大或重排器替换混入本轮实验。

**Tech Stack:** Python 3.12、Pydantic v2、LangGraph、混合检索与 RRF（倒数排名融合）、现有双语查询改写、pytest、Ruff、mypy、私有端到端评测。

## 二、目标数据契约

Planner 中的“事实描述”和“检索查询”职责分离：

```python
class EvidenceFactRequirement(FrozenContract):
    fact_requirement_id: str
    description: str
    search_query: str | None = None
    required_qualifier_kinds: tuple[EvidenceQualifierKind, ...] = ()
    origin: Literal["planned", "derived"] = "planned"
```

- `description`：供事实编译器判断需要证明什么，可以是完整自然语言要求。
- `search_query`：供检索器寻找该事实，只表达一个事实槽位；不得把同单元兄弟事实合并进来。
- `search_query=None` 仅用于读取旧 checkpoint 和旧合成测试；新 Planner 产生的 `origin="planned"` 事实必须显式填写。
- 旧 `origin="derived"` 事实可确定性回退到 `description`，避免旧运行无法恢复。

原子 follow-up 增加事实级追踪：

```python
class EvidenceFollowup(FrozenContract):
    requirement_id: str
    fact_requirement_id: str | None = None
    query: str
    objective: str
```

新生成的 follow-up 必须同时绑定一个单元 `requirement_id` 和该单元中的一个缺失 `fact_requirement_id`。`None` 只为旧 checkpoint 兼容。

@field_validator("search_query")
@classmethod
def normalize_search_query(cls, value: str | None) -> str | None:
