# 对话内 Agent 运行轨迹与紧凑 UI Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将论文研究 Agent 从“等待完成后回放进度 + 常驻三栏控制台”升级为真正实时、可恢复、可折叠的对话内运行轨迹，并把高频功能收敛进对话和输入区。

**Architecture:** 保留 FastAPI、LangGraph、原生 HTML/CSS/JavaScript 与现有统一主 Agent，不迁移前端框架。新增独立于遥测库的安全运行事件账本和内存订阅总线，主图、子执行器和回答输出边执行边发布 versioned NDJSON 事件；浏览器用 reducer 将事件投影为稳定的思考摘要、任务、工具、回答与终态节点，历史记录从同一账本重放。布局改为“可折叠会话导航 + 宽中心对话 + 默认关闭的按需详情抽屉”，计划、审批、RAG、附件、暂停/取消和统计按状态进入对话或 composer。

**Tech Stack:** Python 3.11+、FastAPI `StreamingResponse`、LangGraph、Pydantic v2、SQLite、原生 JavaScript、HTML `<details>`、CSS Grid、unittest/pytest、Playwright。

---

## 一、现状结论

### 1. 当前“流式”并非真实运行流

- `src/paper_research_agent/web/app.py:856-874` 先 `await main_runtime.run(...)`，整个 Agent 完成后才创建响应。
- `src/paper_research_agent/web/events.py:181-205` 将最终 `MainAgentResult` 一次性投影为事件列表；最终回答通常只有一个 `delta`。
- `src/paper_research_agent/web/static/app.js:415-491` 虽然通过 `ReadableStream` 逐行消费 NDJSON，但消费的是事后回放。
- `ConversationChildExecutor` 已经从模型流中读取 `delta`，却在 `src/paper_research_agent/web/child_executors.py:195-215` 全部收集后才返回，实时 token 被丢失。
- 主 Agent 使用 `graph.ainvoke`，节点开始、路由、任务、工具与回答没有统一的面向 UI 的实时发布通道。

### 2. 事件数据不足以成为可恢复的对话记录

- `main-agent-stream-v1` 只有有限类型和计数，没有 `occurred_at`、稳定 `node_id`、父子关系、公开标题/摘要和可安全展示的工具详情。
- `agent-events-v1.sqlite3` 是隐私安全遥测：适合审计和指标，不适合直接渲染；它不应被扩展成产品 transcript。
- 历史 API 只返回 `role/text/status/created_at`，页面刷新后只恢复问答文本，思考摘要、调用链、附件结果、审批和运行状态全部丢失。

### 3. UI 的空间分配与信息优先级相反

- 桌面端固定为约 `14–18rem / 1fr / 16–21rem` 三栏；1440px 验收截图中左右两栏合计占用接近一半宽度。
- 右栏同时承载计划编辑、运行控制、检索路径、上下文预算、运行指标和引用链路，长期常驻但大多数信息只在某一轮或某一步有用。
- 输入框默认高度约 4.8rem，再叠加附件行、两个 checkbox 和 footer，空闲态也持续占用较大高度。
- 移动端把完整语料统计与历史放在对话之前，用户必须先滚过导航信息才能到消息区。
- `pipeline-status` 是固定四步进度条，不能表达动态规划、并行/重试、工具调用、审批、失败和恢复。

## 二、借鉴 DeepSeek Harness 的部分

借鉴其信息模型，不照搬品牌和全部三栏：

1. transcript 由稳定的异构节点构成，而不是“一个回答卡 + 外部进度条”。
2. Think/思考行默认折叠；运行时折叠标题跟随最新安全摘要，完成后稳定为首行摘要。
3. 工具调用保留在发生位置，折叠态展示图标、工具名、摘要、状态和耗时，展开才展示安全参数与结果。
4. 审批、追问、暂停恢复等交互接管 composer，而不是在右侧另开一套控制流。
5. 统计信息靠近本轮尾部或输入区，不常驻占据内容栏。
6. 右侧详情默认关闭，只在用户点开工具、引用或“运行详情”时出现。
7. 对话节点使用稳定 key 和追加更新，流式过程中不销毁 textarea、滚动容器或正在更新的节点。

## 三、产品边界

### 必须实现

- 首个运行事件在请求后立即到达，主图执行期间持续输出节点、任务和工具状态。
- direct chat、附件问答和文件编辑复用现有 provider delta，真实逐 token 输出。
- 本地 RAG 与结构化汇总先保持“验证后分块输出”，但 UI 和协议必须明确标记 `delivery_mode=validated_replay`，不能把它计作 provider 首 token。
- 每轮轨迹可折叠、可恢复、可断线续传、可在历史对话中重放。
- 计划、工具审批、暂停/继续/取消、附件、RAG 模式和运行统计按状态整合进对话/composer。
- 桌面中心内容区优先，右侧详情默认 0 宽；移动端进入页面首先看到当前对话。

### 不做

- 不迁移 React/Vue，不引入第二套状态管理框架。
- 不直接向浏览器或数据库暴露模型隐藏 chain-of-thought、system prompt、原始工具密参、论文正文或召回正文。
- 不用定时器伪造“模型正在思考”的文本。
- 不在本次改造中重写检索、规划或回答质量算法。

### “思考链”的安全定义

产品文案使用“思考过程”或“研究过程”，数据契约使用 `reasoning_summary`。内容只来自当前已存在的安全事实：阶段名、解释后的用户意图、目标变化、任务标题、`execution_reason`、路由能力、工具名、来源数量、验证/降级结果和耗时。原始 provider reasoning、隐藏 CoT、完整 prompt 和未验证草稿不进入事件账本；未来若需要实验 provider reasoning，必须独立 feature flag、默认关闭、禁止持久化并重新做隐私评审。

## 四、目标交互与信息架构

```text
┌──────────────┬──────────────────────────────────────────┬───────────────┐
│ 会话导航      │ 当前对话                                  │ 按需详情       │
│ 248px/52px   │ min 640px，正文 720–880px                 │ 0/320–420px   │
│ 新对话        │ 用户消息                                  │ 工具详情       │
│ 搜索/历史     │ ▸ 思考过程  正在规划  2.4s                │ 引用证据       │
│ ▸ 知识库概况  │ ▸ 计划  1/3 完成                          │ 完整运行指标   │
│ 设置/记忆     │ ▸ 检索论文  9 条来源  ✓  3.1s             │ 计划编辑器     │
│              │ ▸ 调用工具 search_corpus  ✓               │               │
│              │ Agent 回答（流式）                         │               │
│              │ 3 步 · 2 次调用 · 12.8s · 1.6K tokens     │               │
│              │ ┌──────────────────────────────────────┐   │               │
│              │ │ 输入消息…                            │   │               │
│              │ │ ＋  本地论文:优先   [暂停] [停止] [↑]│   │               │
│              │ └──────────────────────────────────────┘   │               │
└──────────────┴──────────────────────────────────────────┴───────────────┘
```

### 对话节点

- `reasoning`：默认折叠；显示当前阶段/安全摘要、状态、耗时。
- `plan`：默认折叠；显示完成/进行中/待办数量。展开看任务标题与状态；编辑动作打开详情抽屉。
- `tool`：每次调用单独一行，按 `node_id` 原位更新 `running -> completed/failed`；参数/结果只展示安全投影。
- `retrieval`：作为专业工具行，折叠态显示查询类型、来源数、是否降级；点击来源数打开引用详情。
- `answer`：真正的 answer delta 追加到同一 DOM 节点；完成后进行引用增强渲染。
- `interaction`：审批、澄清、恢复冲突在消息流中留一条状态记录，实际按钮进入 composer 接管态。
- `turn-tail`：本轮结束时显示耗时、步骤数、调用数、token、复制和“运行详情”。

### Composer

- 默认单行 48–56px，输入后自适应，最大 160px；textarea 内部滚动后不再继续增高。
- 左下只保留 `＋`、附件 chips、RAG 模式 chip；“仅依据本地论文”放入 RAG chip 的弹出菜单。
- 右下是发送/停止主按钮；运行时按权限显示暂停/继续，避免右栏常驻控制。
- 审批等待时 composer 主体替换为审批理由、工具名和“拒绝/允许”；处理后恢复原 textarea DOM。
- 计划处于 paused 时显示“编辑计划”chip，点击打开按需详情抽屉。

### 响应式规则

- `>= 1200px`：导航 248px，可折叠至 52px；详情默认关闭，打开后中心不得小于 640px。
- `768–1199px`：导航默认 52px；详情用 overlay drawer，不挤压对话。
- `< 768px`：导航、知识库和历史进入左侧抽屉；顶部只保留菜单、会话标题、新对话；composer sticky 到安全区底部。
- 空状态的知识库统计改为对话区中的紧凑引导卡，不再占移动端首屏上半部。

## 五、流事件契约 v2

保留 `POST /paper-research/api/agent/runs`，返回 `application/x-ndjson`，协议升级为 `main-agent-stream-v2`。新增只读恢复接口：

- `GET /paper-research/api/agent/runs/{request_id}/events?after_event_id=N`
- `GET /paper-research/api/conversations/{conversation_id}` 的 assistant message 增加 `turn_id`、`request_id`、`run_id` 和 `events`。

公共字段：

```json
{
  "schema_version": "main-agent-stream-v2",
  "event_id": 12,
  "type": "tool_completed",
  "occurred_at": "2026-08-19T08:30:00Z",
  "request_id": "...",
  "run_id": "...",
  "turn_id": "...",
  "node_id": "tool:task-1:search-corpus:1",
  "parent_node_id": "task:task-1",
  "task_id": "task-1",
  "status": "completed",
  "title": "检索本地论文",
  "summary": "找到 9 条来源",
  "duration_ms": 3100,
  "detail": {"tool_name": "search_corpus", "source_count": 9}
}
```

事件类型控制在以下集合：

- 生命周期：`run_started`、`run_reused`、`run_resumed`、`run_paused`、`run_waiting_user`、`run_waiting_approval`、`run_completed`、`run_failed`、`run_cancelled`、`run_conflict`。
- 思考摘要：`reasoning_started`、`reasoning_summary`、`reasoning_completed`。
- 目标与计划：`goal_updated`、`plan_updated`、`task_started`、`task_completed`、`task_failed`。
- 调用链：`tool_started`、`tool_completed`、`tool_failed`、`retrieval_completed`、`file_created`。
- 回答：`answer_started`、`answer_delta`、`answer_completed`。
- 交互：`interaction_required`、`interaction_resolved`。

约束：

- `event_id` 在同一 run 内单调递增；重复连接按 `(run_id, event_id)` 去重。
- `node_id` 在同一 run 稳定，开始/更新/完成复用同一 id。
- `answer_delta` 才允许包含 `delta`；其他事件只能使用限长 `title/summary/detail`。
- 事件先写 SQLite，再无阻塞发布到订阅者；慢客户端丢失内存通知后从 durable cursor 补齐，不能阻塞 Agent。
- 浏览器断开不取消运行；取消只能通过已有显式 control API。
- 重复 `request_id` 返回已有事件并继续订阅，不能重新运行。
- `run_completed/run_failed/run_cancelled/run_conflict` 才是运行终态；`run_paused/run_waiting_user/run_waiting_approval` 只结束当前传输分段，恢复后沿用同一 `run_id` 和连续 `event_id`。
- `answer_delta` 在服务端按 20–50ms 或 64–256 字符合并后持久化，禁止逐 token 开启 SQLite 事务；1000 条是前端性能验收量，不是账本硬截断上限。
- Nginx 保持 `proxy_buffering off`/`X-Accel-Buffering: no`；测试首事件到达时间，而不是只测试响应状态。

## 七、验收指标

### 协议与性能

- `run_started` 在 HTTP 请求建立后 300ms 内可读（不含模型冷启动）；测试必须用未完成 gate 证明非事后回放。
- provider-live 路径首个 `answer_delta` 与底层 provider 首 delta 间额外延迟小于 100ms。
- 每个 run 的事件 id 严格递增，恰好一个终态；断线重连不重复执行。
- 1000 个历史事件首次渲染不阻塞主线程超过 100ms；必要时按 turn 懒加载展开内容。

### 桌面 UI

- 1440px 下中心列实际宽度至少 720px；右侧详情默认关闭。
- 默认 composer 总高不超过 76px；输入两行后自然增高，最大不超过 180px。
- 运行中用户仅看见一组按时间排序的对话内轨迹，不再看固定四步进度条。
- reasoning、plan 和成功 tool 默认折叠；失败/等待审批默认展开。

### 移动 UI

- 390×844 首屏可见当前会话内容和 composer；语料/历史不进入正文流。
- sticky composer 不遮挡最后一条消息，并考虑 `env(safe-area-inset-bottom)`。
- 导航、详情、审批均支持 Escape、遮罩关闭和焦点恢复。

### 隐私与可信度

- 浏览器响应、SQLite 产品事件、日志和 DOM 中均不出现 system prompt、原始 CoT、完整工具密参、API key、论文正文或召回正文。
- “思考过程”只展示可公开摘要；本地 RAG 的验证后分块输出不得标成 provider-live。
- 所有 server text 继续通过 `textContent`/节点构造渲染，不引入 `innerHTML`。

## 八、推荐实施顺序与风险控制

推荐按 Task 1–7 先完成事件真实化与恢复，再做 Task 8–10 UI。不要先把当前事后事件包装成漂亮折叠卡，否则会把伪流式协议固化进新界面。

主要风险：

- **双重事件源**：遥测与产品事件必须单向并列，禁止 UI 直接读遥测 SQLite。
- **流式与验证冲突**：证据约束路径先采用明确标注的验证后分块；只有能保持现有回答验证器不变量的路径才升级为 provider-live。
- **重复执行**：订阅建立、repository `begin_agent_run` 和后台 task 创建必须在同一幂等边界内。
- **慢客户端背压**：Agent 不等待浏览器；durable-first + cursor backfill 是唯一恢复路径。
- **原生 JS 可维护性**：不引入框架，但必须把 event reducer、node renderer、drawer 和 composer machine 分区组织，避免继续扩大单一 `consumeAgentStream` 条件链。

## 九、计划完成定义

以下条件同时满足才算完成：

1. 运行未结束时，浏览器已经能看到真实节点/工具事件。
2. 可流式路径逐 token 更新；验证型路径如实标注 delivery mode。
3. 刷新、重连和切换历史会话后，轨迹仍完整且不重复。
4. 计划、审批、暂停/取消、指标和引用不再要求常驻右栏。
5. 桌面和移动端通过尺寸、键盘、滚动、隐私与浏览器自动化验收。
