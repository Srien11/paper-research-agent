# 多论文比较完整端到端准确率测试 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在不向运行系统泄露目标论文编号、且不修改生产逻辑的前提下，真实评估 30 题从原始用户问题进入主图到最终比较答案与引用的完整链路，并分别报告开发集与 10 题封存集聚合指标。

**Architecture:** 新增仅用于评测的私有金标契约、可观测运行器和确定性评分器；运行器只把原始问题交给生产入口，通过安全探针记录转换、候选、规划、分格检索、证据与引用元数据。严格主图结果与可完成答案的现有 RAG 生产路径分栏记录，任何主图缺链都按端到端失败计分，不能用旁路结果替代。

**Tech Stack:** Python 3.14、Pydantic v2、LangGraph、现有 BM25/FAISS/FastEmbed/Qwen 运行时、pytest、Ruff。

---

### Task 1: 冻结边界、数据契约与失败判定

**Files:**
- Create: `src/paper_research_agent/evaluation/comparison_end_to_end.py`
- Create: `tests/evaluation/test_comparison_end_to_end.py`
- Verify: `data/evaluations/gold/candidate-paper-gold-v1.jsonl`
- Verify: `.gitignore`

**Step 1:** 定义私有端到端金标模型，包含 `expected_dimensions`、`must_have_claims`、权威原文 span/派生 `evidence_chunk_ids`、`forbidden_claims`、`citation_relations`，并强制题号、split、目标集合与候选金标一致。

**Step 2:** 定义隐私安全逐题诊断模型，只允许保存问题 SHA-256、转换状态/耗时/保留检查、Top 8/最终对象、维度、分论文分维度检索元数据、chunk ID、引用关系、耗时和错误类型，不允许保存问题、摘要、正文或答案。

**Step 3:** 写失败测试，证明运行请求只含原始问题和运行标识，不含 `relevant_paper_ids` 或其他金标字段；评分器在运行结束后才加载金标。

**Step 4:** 写失败测试，封存集序列化只能产生聚合指标，不能产生题目、目标编号或逐题答案。

### Task 3: 实现只读可观测端到端运行器

**Files:**
- Create: `scripts/evaluate_comparison_end_to_end.py`
- Create: `src/paper_research_agent/evaluation/comparison_end_to_end.py`
- Create: `tests/evaluation/test_comparison_end_to_end.py`

**Step 1:** 从现有候选金标加载题目，但构造运行请求时只传原始 `question`；相关论文编号只保留在独立评分对象中。

**Step 2:** 对主图入口加评测侧安全探针，记录主图最开始的语义解释/转换、候选发现、规划、检索与子图结果；探针不得记录正文。

**Step 3:** 对答案链记录最终 claim/citation 元数据，并通过本地 chunk catalog 反查 corpus 归属；不得把证据正文写入运行 JSON 或公开报告。

**Step 4:** 为每题使用独立 conversation/thread/request ID，设置问题转换 10 秒和整体 120 秒超时，逐题原子落盘并支持恢复。

### Task 4: 补充私有端到端评分数据

**Files:**
- Create (Git ignored): `data/evaluations/gold/comparison-end-to-end-gold-v1.jsonl`
- Create (Git ignored): `data/evaluations/gold/comparison-end-to-end-gold-v1.meta.json`

**Step 1:** 仅从每题目标论文的本地原文与 chunk catalog 提取候选事实和权威跨度，禁止使用候选干扰论文事实填充必要事实。

**Step 2:** 为 30 题逐题生成比较维度、必要事实、禁止事实和事实—证据关系；记录生成方法与校验状态，不宣称不存在的人工标注。

**Step 3:** 校验每个证据 chunk/span 属于目标论文、每个必要事实至少有一个 citation relation、禁止事实不与必要事实冲突。

**Step 4:** 把 GQ016 类单论文识别和 GQ017 类跨论文多跳仅作为题型差异处理，不增加题号分支或硬编码论文编号。
