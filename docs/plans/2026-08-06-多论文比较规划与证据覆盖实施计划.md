# 多论文比较规划与证据覆盖 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让开启本地论文能力后的复杂比较问题自动进入受约束的研究图，并通过“比较对象 × 比较维度”覆盖矩阵驱动分步检索、缺口补检索和带证据综合。

**Architecture:** 保留普通聊天和单轮 RAG；新增轻量研究意图策略，只把明确的论文/方法/模型比较送入 Research Agent。扩展现有 ResearchPlan 与 EvidenceAssessment 契约，使规划器生成比较目标、维度、证据要求和目标化查询，图在每轮评估后确定性校验覆盖矩阵，未覆盖时继续计划或定向补检索。最终上下文携带安全的覆盖状态，并要求回答器逐维度、逐对象引用。

**Tech Stack:** Python 3.14、Pydantic v2、LangGraph、LangChain structured output、FastAPI、unittest。

**Files:**

- Modify: `src/paper_research_agent/web/app.py`
- Test: `tests/agent/test_intent.py`
- Test: `tests/web/test_routing.py`

**Steps:**
1. 写失败测试：明确的论文、模型、方法比较在 `preferred` 且 RAG 可用时强制走 `local_rag`；普通聊天和 `disabled` 不受影响。
2. 实现保守的 `requires_research_planning(question)`，同时要求比较信号和研究对象信号，避免泛化成所有“比较”表达。
3. 将原始问题加入服务端 RouteContext，并在策略层落实证据义务。
4. 运行 `python -m unittest tests.agent.test_intent tests.web.test_routing -v`。

### Task 2: 比较计划与覆盖契约

**Files:**
- Modify: `src/paper_research_agent/agent/models.py`
- Test: `tests/agent/test_models.py`

**Steps:**
1. 写失败测试：comparison plan 必须至少有两个目标、一个维度，以及完整的目标×维度证据要求。
2. 增加 ResearchTarget、ResearchDimension、EvidenceRequirement、EvidenceCoverage 契约。
3. 扩展 ResearchStep 的 target_ids/dimension_ids，扩展 ResearchPlan 的 task_type/targets/dimensions/requirements。
4. 扩展 EvidenceAssessment 的 coverage 与 next_requirement_ids，并保持 direct 计划向后兼容。
5. 运行 `python -m unittest tests.agent.test_models -v`。

### Task 3: 规划器与证据评估器提示词

**Files:**
- Modify: `src/paper_research_agent/agent/planner.py`
- Modify: `src/paper_research_agent/agent/reasoner.py`
- Test: `tests/agent/test_planner.py`
- Test: `tests/agent/test_reasoner.py`

**Steps:**
1. 写失败测试：多论文比较必须要求逐对象查询和完整覆盖网格，reasoner 输入必须携带 requirements。
2. 更新 planner system prompt：识别目标、维度，禁止用一个宽泛查询替代所有对象的检索。
3. 更新 reasoner system prompt：逐 requirement 返回覆盖证据，只能引用已提供 chunk_id，缺口查询必须绑定 requirement。
4. 运行 planner/reasoner 单测。

### Task 4: 图内确定性覆盖门禁与动态补检索

**Files:**
- Create: `src/paper_research_agent/agent/coverage.py`
- Modify: `src/paper_research_agent/agent/graph.py`
- Modify: `src/paper_research_agent/agent/runtime.py`
- Test: `tests/agent/test_coverage.py`
- Test: `tests/agent/test_graph.py`
- Test: `tests/agent/test_runtime.py`

**Steps:**
1. 写失败测试：不存在的 chunk、缺 requirement、覆盖未满却声明 sufficient 均被拒绝。
2. 实现 coverage validator，校验 requirement 完整性、chunk 来源和 sufficiency 一致性。
3. 动态 replan 继承缺口对应的 target_ids/dimension_ids，不允许无目标的宽泛补检索。
4. 在安全 task_state 中保存 requirement 状态和 chunk_id，不保存证据正文。
5. 运行图和 runtime 单测。

### Task 5: 自动选择固定 RAG 或研究图，并约束比较回答

**Files:**

- Modify: `src/paper_research_agent/context/assembler.py`
- Test: `tests/web/test_runtime.py`
- Test: `tests/context/test_assembler.py`

**Steps:**
1. 写失败测试：auto 模式只对复杂比较启用 Research Agent，普通本地问答仍走单轮 RAG。

3. 为 comparison task_state 增加逐维度、逐目标、逐 claim 引用规则，未覆盖单元不得推断。
4. 运行 runtime 和 context 单测。

### Task 6: 配置、回归与真实对照

**Files:**
- Modify: `.env`（仅增加非密钥开关，不输出已有值）
- Modify: `reports/RAG银标Rubric诊断-v1.md` 或新增对照报告

**Steps:**
1. 本地启用 `PRA_RESEARCH_AGENT_ENABLED=true` 与 `PRA_RESEARCH_AGENT_MODE=auto`。
2. 运行 agent/web/context 目标测试，再运行完整测试套件、ruff 和 py_compile。
3. 重启服务并验证 health、ready、登录和普通 RAG 不回归。
4. 在多论文比较银标切片上运行现有纯 RAG 与新研究图配对评测，分别记录 Paper/Span/Requirement/Claim Recall、错误拒答、延迟和 Token。
5. 若真实模型结构化输出不满足新契约，修复 planner/reasoner 输出边界，不用静默降级伪造覆盖。
