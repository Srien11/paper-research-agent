# 短期记忆与上下文优化实施计划

## 目标

为问题级 RAG 增加可配置、按会话隔离的本地短期记忆，使连续追问能够复用最近对话，
同时保证论文证据仍是事实回答的唯一权威来源。

## 边界

- 短期记忆是上下文的可选组成层，不等于完整上下文。
- 完整上下文仍由系统规则、当前问题、短期记忆、检索证据和输出契约组成。
- 记忆只保存用户问题、已验证 claims 的纯文本摘要、来源 chunk ID 和版权分类，不保存旧
  引用编号、完整 answer markdown、证据正文、模型请求体或原始响应。
- 记忆不得充当论文证据；事实声明仍必须引用本轮检索得到的 `E<number>`。
- 未提供 `session_id` 时保持完全无状态，兼容当前 CLI 和服务调用。

## 默认策略

- 本地 SQLite，schema `short-term-memory-v1`。
- TTL 24 小时，每个 session 最多持久化 20 轮。
- 每次最多读取最近 6 轮，注入预算最多 1200 个保守估算 Token。
- session ID 必须显式提供并限制为安全字符。
- 仅当当前问题明显依赖上文时，用上一轮用户问题扩展检索式；不发送旧证据正文。
- 记忆存储或读取故障采用 fail-open：回答仍可继续，但不能污染结果或泄露内部异常。

## 实施步骤

### 1. 数据契约与配置

- 新增短期记忆配置、turn、引用定位和上下文 turn 契约。
- 验证 session ID、TTL、轮数、Token 预算和路径安全。
- 测试额外字段、空文本和非法配置均失败关闭。

### 2. SQLite 生命周期

- 实现 append、recent、按 TTL 清理和按 session 数量裁剪。
- 启用 WAL、busy timeout 和线程锁。
- 数据库不包含 evidence/context/provider payload 字段。

### 3. 上下文选择与检索消歧

- 将最近 turn 转成规范 JSON 的不可信记忆消息，防止历史内容注入系统规则。
- 先保证系统规则、当前问题和至少一个可容纳的检索证据，再使用剩余记忆预算。
- 对短小且包含指代词的追问，拼接上一轮用户问题作为检索背景。

### 4. RAG 与 CLI 接入

- `answer_question` 支持可选 session/store/policy。
- `scripts/rag.py` 增加 `--session-id`、`--memory-config`、`--memory-path`。
- 未启用 session 时输出和行为保持兼容。
- 本轮验证回答完成后才写入记忆。

### 5. 验证

- 单元测试覆盖隔离、TTL、裁剪、注入、Token、追问消歧和无状态兼容。
- 使用假模型执行两轮连续问答，证明第二轮检索式使用上一轮主题。
- 运行全量测试、变更文件 Ruff、目标模块 Mypy 和 `git diff --check`。
