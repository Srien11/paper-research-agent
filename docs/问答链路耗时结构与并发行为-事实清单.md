## 1. 入口与路由选择

**【事实】**

- 运行模式由环境变量决定，**默认 `legacy`**：`src/paper_research_agent/web/bootstrap.py:438-459`（无 `PRA_MAIN_AGENT_MODE`、无 `PRA_MAIN_AGENT_ENABLED` 时返回 `"legacy"`）。
- 仅当 `environment.mode == "primary"` 时才创建 main agent runtime：`bootstrap.py:494-566`。
- 因此 `legacy` 模式下 `app.state.main_agent_runtime` 为 `None`，`GET/POST /api/agent/runs` 直接返回 503：`src/paper_research_agent/web/app.py:894-901`。
- `legacy` 模式下的问答接口有两个，且都不走兼容分支：
  - 流式 `/api/chat/stream`：`app.py:1720`
  - 非流式 `/api/ask`：`app.py:1567`（`primary` 分支在 `:1582-1591`，`legacy` 分支从 `:1592` 开始）
- 流式接口在 `main_agent_mode == "primary"` 时改走兼容路径并**立即返回**：`app.py:1733-1737`；否则进入 `events()` 生成器：`app.py:1745`。
- 轮次准备 `_prepare_turn`：`app.py:313`；**优先调用 `interpret_turn`**（若该 runtime 提供）：`app.py:334-343`；否则退化为 `coordinator.begin` + `classify_route`：`app.py:364-383`。
- `interpret_turn` 是**一次模型调用**，参数为 `temperature=0`、`max_tokens=500`、`response_format=json_object`、`enable_thinking=False`：`src/paper_research_agent/web/chat_runtime.py:185-250`（payload 在 `:194-230`）。
- 该调用失败时最多重发 1 次（共 2 次尝试）：`chat_runtime.py:232`。
- `events()` 内的分支链依次判断：`local_rag`（`app.py:1865`）、`web_research`（`app.py:1898`）、`attachment_qa` 与 `file_edit` 共用同一分支（`app.py:1984-2000`）、其余情况走普通交流流式（`app.py:2001-2002`）。

## 2. `local_rag` 链路的输出时序与串行结构

### 2.1 输出时序（关键事实）

**【事实】** `app.py:1865-1896` 分支中：

```python
result = await _runtime_ask(rag_runtime, payload.question, ...)   # app.py:1868
...
yield json.dumps({"type": "rag_result", ...})                     # app.py:1886
```

在该 `await` 完成之前，该分支**不产出任何字节**。分支内首个输出即完整结果。
即：`route` 事件（`app.py:1792-1813`）之后到 `rag_result` 之间没有任何中间事件。

**【事实】** 非流式接口 `/api/ask` 在 `legacy` 模式下同样先 `await` 完整结果再返回：`app.py:1615-1620`。

**【事实】** 所有流式响应均设置 `X-Accel-Buffering: no`：`app.py:951`、`app.py:1027`、`app.py:2040`。

### 2.2 `RAGRuntime` 内部串行顺序

**【事实】** `src/paper_research_agent/web/runtime.py:791-939` 的 `_execute`：

1. 判断是否使用研究 agent：`runtime.py:817-821`
2. 分支 A（不用研究 agent）：单次检索 `runtime.py:823-827`
3. 分支 B（用研究 agent）：`research = await self._research_agent.run(...)`：`runtime.py:839-846`
4. 组装上下文：`runtime.py:855-914`
5. 生成答案：`runtime.py:915-919`（`answer_context`）或 `runtime.py:906-910`（对比模式 `answer_comparison`）
6. 写短期记忆：`runtime.py:922`
7. 构造返回：`runtime.py:933`

以上步骤在同一协程内顺序执行，步骤 3 与 5 之间没有并发。

### 2.3 答案生成的重试与超时

**【事实】**

- `answer_context` 对生成器的调用**最多 2 次**：`src/paper_research_agent/answering/service.py:29`（默认 `max_validation_attempts=2`）、循环在 `:54`。引用校验失败会重新调用模型：`:68-77`。
- 生成器单次请求内部重试上限由配置决定，当前配置为 `max_retries=2`（最多 3 次尝试）：`configs/answering/qwen-rag-v1.json:9`；循环在 `src/paper_research_agent/answering/dashscope.py:115`。
- **整个重试循环被一个总的 30 秒期限包住**：`dashscope.py:114`（`async with asyncio.timeout(self._config.timeout_seconds)`），`timeout_seconds=30` 来自 `configs/answering/qwen-rag-v1.json:8`。
- 退避为 1/2/4 秒（上限 4）：`dashscope.py:263-264`；HTTP 429/5xx 优先使用 `Retry-After`：`dashscope.py:253-260`。
- 答案请求使用 `response_format={"type": "json_object"}`：`dashscope.py:103`；`enable_thinking` 由配置给出，配置文件为 `false`：`configs/answering/qwen-rag-v1.json:10`。

### 2.4 检索内部（此段已并发）

**【事实】** `src/paper_research_agent/retrieval/bilingual.py:135-276` 的 `search()`：

- 查询改写以 `create_task` 启动，同时中文召回提交到本地线程池执行器：`bilingual.py:178-192`

**改写缓存**（决定改写是否真的发生）：

## 3. `web_research` 链路的串行结构

**【事实】** `app.py:1898-1982` 分支：

1. 若 `use_local_papers`：`await _runtime_ask(...)` 跑完整本地 RAG：`app.py:1903-1910`
2. 若 `use_dynamic_tools` 或 `use_web_research`：`await rag_runtime.run_tool_research(...)`：`app.py:1931-1935`
3. 两者完成后再 `conversation.complete` 与产出事件：`app.py:1939-1981`

步骤 1 与 2 之间没有并发。

**【事实】** 两者使用**同一个 runtime 实例**：

- 本地变量取自 `request.app.state.runtime`：`app.py:1751`
- 该实例在 lifespan 中赋值：`app.py:758-759`
- 每个进程一个实例：`bootstrap.py:490-492`

**【事实】** 该实例上 `ask` 与 `run_tool_research` **都会抢占同一个 `_busy` 闸门**：

```python
if self._busy: raise RuntimeBusyError("RAG runtime is busy")   # runtime.py:685-686 / :719-720
self._busy = True                                             # runtime.py:691    / :721
async with self._execution_lock:                              # runtime.py:693    / :723
```

**【推断】** 因此把步骤 1、2 改为并发（如 `asyncio.gather`）在**当前代码下会失败**：后进入者会抛 `RuntimeBusyError`。
验证方式：见第 9 节 V3。

## 4. 研究 agent 的循环结构

### 4.1 图结构与循环

**【事实】** `src/paper_research_agent/agent/graph.py:814-850`：

```
START → plan → reason
reason --(next_action)--> execute_tools | assess_evidence | finalize
execute_tools --(条件)--> reason | assess_evidence
assess_evidence → reason
finalize → END
```

- `assess_evidence` 每次执行都会调用一次模型：`graph.py:724`（`await reasoner.assess(...)`）
- `assess` 是单次模型调用（结构化输出，失败时最多重发 1 次）：`src/paper_research_agent/agent/reasoner.py:51-231`，重发逻辑在 `:146`、`:199-213`
- 研究 agent 整体完成后，**另有独立的一次答案生成调用**：`web/runtime.py:839` → `web/runtime.py:915`（或 `:906`）

### 4.2 每次迭代的观察数与评估数约束（**关键**）

**【事实】** `direct`（非对比）计划要求观察数与评估数严格相等：

```python
if not is_comparison and len(assessments) != len(observations):
    raise ValueError("research assessments do not match observations")
```
`graph.py:264-265`

**【事实】** `comparison`（对比）计划允许评估数 ≤ 观察数：

```python
if is_comparison and (not assessments or len(assessments) > len(observations)):
    raise ValueError("comparison assessments do not match observation batches")
```
`graph.py:266-269`

**【事实】** 代码中已有按**批次**记账的字段 `assessment_observation_counts`：`graph.py:766-769`。

### 4.3 批量大小

**【事实】** `graph.py:588-594`：

```python
batch_size = 1
if plan.task_type == "comparison":
    batch_size = min(runtime_policy.comparison_search_concurrency, len(plan.steps) - current_step)
```

即：**非对比任务每次迭代固定执行 1 个检索步骤**；对比任务可批量。

- `comparison_search_concurrency` 默认 6：`src/paper_research_agent/agent/policy.py:14`
- 批量内部的检索与证据获取已使用 `asyncio.gather`：`graph.py:618-623`、`graph.py:643-656`

### 4.4 批量能力的现状（哪些组件已支持多观察）

**【事实】** 以下组件对多观察（批量）**已经是就绪的**：

| 组件 | 现状 | 位置 |
| --- | --- | --- |
| 直连计划的证据拼装 | 遍历全部 `observations`，按 `chunk_id` 去重 | `reasoner.py:782-813` |
| 直连计划的评估提示词 | 传入 `search_history` 列表 | `reasoner.py:87-98` |
| 直连计划的评估校验 | 仅要求 `coverage`/`ledger`/`next_requirement_ids`/`followups` 为空 | `src/paper_research_agent/agent/coverage.py:170-178` |
| 补全 follow-up | 非对比计划直接返回，不做处理 | `coverage.py:521-529` |

**【事实】** 4.2 中的 `graph.py:264-265` 是**已知的硬性阻碍**：只要一次迭代产出多于 1 个观察，下一次进入 `reason` 就会抛 `ValueError`。
**【未验证】** 除该处外，是否还有其他模块依赖「direct 计划评估数 = 观察数」这一假设，本文档未做穷尽审计（见第 7 节 U11）。

### 4.5 预算与代码常量

**【事实】** 默认预算（可用环境变量覆盖）：`web/runtime.py:1454-1474`

| 参数 | 默认值 | 环境变量 |

## 5. 并发与生命周期

**【事实】**

- `RAGRuntime` 为**单飞**语义：`_busy` 标志 + `asyncio.Lock`：`runtime.py:326-327`；检查与设置在 `:685-704`（`ask`）、`:719-729`（`run_tool_research`）、`:741-751`（`resume_tool_research`）、`:758-765`（`list_long_term_memories`）。

- `ConversationRuntime` 同样单飞：`chat_runtime.py:95-97`（`_lock`/`_busy`）；`stream_chat` 在 `:306-316`（`_busy` 检查在 `:308`），`stream_contextual_chat` 在 `:387-395`。
- 全局单实例：`app.py:758-759`、`bootstrap.py:490-492`、`bootstrap.py:567-574`。
- **按会话加锁的正确范式已存在于仓库内**：`src/paper_research_agent/agent/orchestrator/runtime.py:78`（注释 `Serialize one conversation at a time; different conversations run in parallel.`）、`:106-109`、`:838-843`。
- 主 agent 在途运行上限默认 2：`bootstrap.py:155-161`（`PRA_MAIN_AGENT_MAX_INFLIGHT_RUNS`）。
- 并行混合研究**默认关闭**：`bootstrap.py:150-154`（`PRA_PARALLEL_HYBRID_RESEARCH_ENABLED` 默认 `False`）；关闭时会返回 `parallel_hybrid_disabled`：`agent/orchestrator/graph.py:466-496`。

- `run_event_publisher` **只在 `primary` 模式注入**：`bootstrap.py:508`、`:531`、`:541`、`:559`（均在 `:494` 的 `primary` 分支内）。
