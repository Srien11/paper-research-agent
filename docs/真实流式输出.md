# 真实流式输出

研究台原有的论文回答先等待完整模型 JSON 和引用校验，再分块发送正式正文。这次把模型的增量输出接入研究台原有的问答入口，无须额外按钮。

## 生成与确认

- 论文问答使用供应商的 SSE 流式接口；逐段解析 `delta.content`，仅投影 `claims[].text`，不展示推理字段、JSON 字段或引用元数据。
- 多任务综合回答使用模型的流式工具调用参数，提前展示 `conclusion`；审批恢复后的综合回答也使用同一路径。
- 页面实时显示“生成中，待校验”。这是供应商正在生成的正文预览，没有人为逐字播放或延时。
- 完整回答仍须通过原有结构、引用和提交校验，随后替换预览及子任务回答，显示正式结果。重试清空旧草稿，失败、取消、断线或终止时移除预览。
- 已有的精确缓存命中及确定性论文对比渲染没有新的模型生成过程，可以直接展示正式答案。

## 数据与传输边界

新增 `main-agent-preview-v1` NDJSON 快照事件，包含 request/run/node 标识、单调序号和最多 20,000 字符的正文。事件总线只向同一 request 的已授权订阅发送预览；预览不写 SQLite、审计、历史或断线续传游标，不保存到浏览器历史。

预览回调通过请求上下文隔离，退出时还原。供应商 JSON/参数累计上限为 262,144 字符，解析深度上限为 32。论文预览约每 40 毫秒合并一次；订阅队列满时丢弃临时快照，正式事件仍由持久化账本恢复。重连只能恢复正式事件及之后的新预览。

正式事件继续使用 `main-agent-stream-v2`，保留来源元数据和已有鉴权。跨子任务重复且不一致的引用编号不合并为可点击来源，避免指向错误证据；最终事件的来源集合受既有事件大小限制。

## 验证

测试通过可控暂停点阻止供应商完成响应，确认此时已收到非空预览，最终回答任务仍未结束；综合模型的工具参数流也使用相同验证方式。另覆盖不完整转义、Unicode、异常结束、截断响应、超时、取消、重试替换、引用校验重试、请求隔离、内存事件不落盘、不推进游标、队列溢出与最终答案替换。

本地真实供应商连通测试只使用合成证据，不写研究台会话：首次正文预览实测约 1,250 毫秒，完整生成及引用校验约 1,644 毫秒，共 4 次非空预览。这是短合成问题的实际运行测量，不是完整论文检索链路的耗时或其速度保证。

综合模型也做了真实供应商调用：使用两条合成子任务结果，首次结论预览约 3,389 毫秒，总计约 4,972 毫秒，收到 14 次非空预览，最终保留两条来源，未触发确定性降级。

真实流式改善生成阶段的等待体验，不会消除生成前的检索、规划或证据准备时间，也不改变模型参数和引用校验要求。

## 刷新恢复

刷新只订阅原 request 的事件，不创建问答或再次调用模型。页面从服务端快照中的原 node ID、正文及事件游标重建运行状态，再接收后续事件；不再把快照正文放进一个额外回答节点，也不把浏览器游标直接套用到另一时刻的快照。

已结束的历史运行会清理残留的待接收标记，不再创建新的回复面板。续传完成更新同一条历史消息，避免追加重复回答。连接提前结束而未收到终止事件时保留待接收状态，不把不完整输出误记为完成。未校验预览仍不落盘，因此刷新会清掉这部分临时正文，只接收原运行之后产生的新预览。

2026-10-06 实际失败记录的根因是提交校验错误要求跨任务来源 ID 全局唯一：3 个子任务共引用 7 次、涉及 5 个不同来源，合法的复用导致整轮运行失败。现改为单个子任务内不得重复，同一来源不得跨不同来源类别复用；同类任务可重复使用同一来源，写入汇总时仍去重。用原失败检查点重新执行校验已通过，没有模型调用，也没有修改旧运行状态。

失败、取消或暂停的页面与历史记录保留 `answer_completed` 的子任务正文及各自引用，并标注“已完成部分（本轮运行尚未完成）”。未完成的增量和临时预览不作为可恢复答案展示。旧失败记录不会被改写成成功记录。

浏览器刷新离开页面时主动关闭流连接，不把取消连接保存成失败回答。续传遇到短暂网络错误时最多重试 3 次，始终对原 request 发 GET，并从当前已展示游标继续；不重新发问答 POST。订阅初始化被取消或失败时立即清理，防止反复刷新留下订阅。连通性检查连续执行了 80 个带认证的会话、历史及事件读取请求，全部返回 200；这项检查本身不等同于复现截图中的运行失败。
