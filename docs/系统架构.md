# 系统架构

```text
冻结语料清单 + 本地 PDF
  -> 语料校验门禁
  -> 确定性文档解析
  -> 类型化元素与稳定片段
  -> 向量 / BM25 索引
  -> 上下文组装（预算、去重、引用、信任隔离）
  -> 检索实验执行器
  -> 评测报告
  -> 研究 Agent 工作流
```

## 信任边界

- PDF 内容是不可信数据，不能改变系统指令或工具权限。
- 清单记录是导入入口，但仍需通过 Pydantic 契约和完整性检查。
- 本地绝对路径不得出现在公开评测产物中。
- 模型输出不能直接执行删除、网络或数据库写操作。
- 对话历史、任务状态和检索证据均是低信任数据，只能位于 system 消息之后。
- 证据中的提示词或伪造角色只能作为 canonical JSON 字符串数据，不能改变消息角色。

## 上下文消息层级

```text
可信 system 规则 + 固定信任策略
  -> 必要的 user / assistant 对话历史
  -> 当前 user 问题与任务状态（不可信数据）
  -> 检索证据（不可信 canonical JSON 数据）
```

输入预算先扣除输出预留，再完整计算最终渲染消息。系统规则和当前问题不做静默截断；
固定内容超出预算时关闭失败。证据按 `(final_rank, chunk_id)` 稳定选择，相同正文哈希
只保留最高排名来源，单条证据无法完整放入时直接省略。

## 产物血缘

每个派生产物必须能追踪到：

```text
corpus_version
source_pdf_sha256
parser_name + parser_version
chunk_schema_version + chunk_config_hash
embedding_model + embedding_revision
index_build_id
evaluation_dataset_version
code_commit
```

首版检索结果必须返回 `corpus_id`、`element_id`、`chunk_id`、`page`、检索分数和原文证据。

## 数据接入层次

V0 派生产物按以下层次组织：

```text
documents -> assets -> pages -> sections -> elements -> chunks
```

- `documents` 保存规范论文实体与默认证据版本。
- `assets` 绑定具体 PDF、来源和 SHA-256。
- `pages` 区分 PDF 索引、显示页码、原文和归一化文本。
- `sections` 保存标题路径和父子关系。
- `elements` 保存正文、表格、图片、公式和参考文献及其坐标。
- `chunks` 只保存检索单元，并通过元素位置区间回指原始证据。

同一输入和配置重复运行时，ID、记录数和输出哈希必须一致。
