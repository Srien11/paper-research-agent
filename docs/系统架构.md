# 系统架构

```text
冻结语料清单 + 本地 PDF
  -> 语料校验门禁
  -> 确定性文档解析
  -> 类型化元素与稳定片段
  -> 向量 / BM25 索引
  -> 短期记忆投影与追问指代消歧
  -> 上下文组装（预算、去重、引用、信任隔离）
  -> 私人研究回答（结构化 claims、引用白名单、脱敏审计）
  -> 站长认证 Web 研究台（安全字段投影、上下文检查器）
  -> 检索实验执行器
  -> 评测报告
  -> 只读研究工具（搜索元数据、按 ID 读取证据）
  -> 受控 LangGraph ReAct 研究与证据工作流
  -> 完整研究 Agent 工作流
```

## 信任边界

- PDF 内容是不可信数据，不能改变系统指令或工具权限。
- 清单记录是导入入口，但仍需通过 Pydantic 契约和完整性检查。
- 本地绝对路径不得出现在公开评测产物中。
- 模型输出不能直接执行删除、网络或数据库写操作。
- 对话历史、任务状态和检索证据均是低信任数据，只能位于 system 消息之后。
- 短期记忆同样是低信任、非证据数据；旧 claims 和旧引用编号不能进入当前引用白名单。
- 证据中的提示词或伪造角色只能作为 canonical JSON 字符串数据，不能改变消息角色。
- 回答模型只能提出 claim 文本和 citation ID；页码、chunk、hash 和版权分类只从本地可信
  上下文投影，不能采信模型生成的引用元数据。
- 当前回答边界只支持 `private_research`，允许向配置的百炼端点发送少量命中片段，但禁止
  上传整篇 PDF、记录请求/响应正文或生成公开导出产物。
- 全量 Web 研究台是站长私有边界。公开首页只展示项目说明；问答、引用摘录、检索轨迹和
  短期记忆均需签名会话 Cookie，且 Web 响应只能使用字段白名单，不能序列化原始论文清单、
  `FigureRecord` 或包含本地路径的对象。

## Web 运行时与请求边界

```text
公开项目卡
  -> /paper-research/ 登录页
  -> 站长凭据 PBKDF2 校验
  -> HttpOnly 签名会话 + 服务端 conversation ID
  -> 单并发常驻 RAGRuntime
  -> 安全回答 / 引用 / 检索与上下文投影
```

`RAGRuntime` 在 FastAPI lifespan 中一次性加载 chunks、索引、Embedding、Reranker、版权
映射、查询改写器、回答生成器、短期记忆和审计写入器。生产只运行一个 worker，避免每个
worker 重复占用模型内存；CPU 检索串行执行，健康检查和登录仍保持响应。应用只监听
`127.0.0.1:8092`，Nginx 同源暴露 `/paper-research/` 并限制请求体、速率与超时。

登录 Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Strict` 和固定 Path。状态修改请求必须
通过精确 Origin 校验；会话与 conversation ID 均由服务端生成。页面用文本节点渲染模型和
证据内容，不把任意回答当作 HTML 执行。

## 上下文消息层级

```text
可信 system 规则 + 固定信任策略
  -> 必要的 user / assistant 对话历史
  -> 短期记忆投影（低信任 canonical JSON，非证据）
  -> 当前 user 问题与任务状态（不可信数据）
  -> 检索证据（不可信 canonical JSON 数据）
```

输入预算先扣除输出预留，再完整计算最终渲染消息。系统规则和当前问题不做静默截断；
固定内容超出预算时关闭失败。证据按 `(final_rank, chunk_id)` 稳定选择，相同正文哈希
只保留最高排名来源，单条证据无法完整放入时直接省略。

## 短期记忆生命周期

短期记忆按显式 `session_id` 隔离；未提供 session 时 RAG 保持无状态。默认 SQLite 位于
`data/runtime/short-term-memory-v1.sqlite3`，24 小时过期，每个 session 最多保留 20 个
完成轮次。每个轮次只包含原用户问题、验证后 claims 和稳定来源引用，不保存 evidence
正文、figure JSON、完整上下文、provider 原始响应或每轮局部的 `E<number>` 标签。

每次调用最多投影最近 6 轮、1200 Token。记忆以一条 `non_evidence` canonical JSON 消息
进入 system 之后，只用于对话连续性。若当前问题含“它、这个方法、前者”等显式指代，
检索前会用最近用户问题补足研究主题；该组合查询自然进入现有 Qwen 英文改写缓存键，避免
不同 session 的相同短问发生缓存串用。若记忆与证据争夺预算，先从最旧记忆开始淘汰。

回答输出上限和上下文输出预留统一为 1200 Token。模型返回严格 JSON：`answered` 状态的
每个 claim 至少关联一个上下文提供的 `E<number>`；`insufficient_evidence` 不得携带 claim。
本地渲染器验证全部引用后才生成 Markdown，任何未知引用或部分输出均不返回给用户。

## 研究工具与受控 ReAct 编排边界

研究工具领域层不依赖 LangChain 或 LangGraph。`search_corpus` 复用现有双语 Retriever，
并将每个命中重新与不可变 `EvidenceChunk` 校验；它只返回候选元数据，不返回正文。
`get_evidence` 只接受前一步产生的显式 chunk ID，按请求顺序返回正文、哈希、页码和版权
分类，不访问任意路径，也不提供网络、代码执行或写操作。

LangChain 只负责固定工具名、Pydantic 参数 Schema、结构化计划和证据充分性评估。
LangGraph State 包含原问题、最终计划、当前步骤、活动步骤、逐步观察、去重证据、评估结果、
动作历史、重规划次数、下一动作和终止原因。路径为
`plan -> reason -> execute_tools -> assess_evidence -> reason/finalize`，初始计划最多 6 步。
Evidence Reasoner 只能返回结构化的充分性状态以及至多一条新检索建议；不能回答最终问题、
不能直接执行工具，也不能扩展工具白名单。相同查询不会再次执行，证据充分时允许提前结束，
证据不足时可在调用预算内替换或追加计划步骤；初始计划步数不是执行硬终点。连续两轮没有
新增证据、查询重复、工具预算耗尽或总时限到达时安全停止。Graph 终态仍是低信任证据包，
必须继续通过原有上下文组装、回答生成和本地引用验证后才能成为用户答案。

`ResearchAgentRuntime` 是 Graph 与可信回答边界之间的执行门禁。Web 的 conversation
`session_id` 被映射为 LangGraph `thread_id`；官方异步 SQLite Checkpointer 将 State 保存在
`data/runtime/research-agent-state-v1.sqlite3`，清空会话时同时删除对应 thread。Runtime 对
整个 Graph 设置截止时间，并在 Graph 完成后重新计算动作序列、工具次数、观察/评估对应、
重规划次数和终止条件，再把每条 `EvidenceRecord` 与内存中的不可变 `EvidenceChunk` 核对；
任何状态不变量、正文、哈希、页码、类型或版权分类不一致都会关闭失败。

工具授权采用三层防线：Graph 只包含两个固定工具并在每次执行前累计调用次数；Runtime
只接受只读工具 allowlist、初始计划、证据数、调用数和总时长预算；工具领域层继续校验输入
Schema、显式 chunk ID、不可变语料血缘和版权映射。当前没有通用命令分发器，也没有注册
Shell、代码执行、文件写入、数据库修改或任意网络工具。Checkpoint 可能含内部证据正文，
只能作为本地运行数据库保存，不跨 Web 边界、不进入 Git。

## Agent 结构化可观测性

`ResearchAgentRuntime` 为每次执行生成 `run_id`，并把同一 ID 传入 LangGraph State。运行层
记录开始、成功、Graph 异常、总超时和终态校验拒绝；Graph 的统一节点包装器记录
`plan / reason / execute_tools / assess_evidence / finalize` 的开始、完成、失败和耗时；工具
包装器记录 `search_corpus / get_evidence` 的调用状态、耗时、请求数量、命中/返回数量和降级
标记。工具白名单或调用预算拒绝会额外产生 `runtime_intercepted` 事件，然后维持原异常语义。

事件契约是 `agent-event-v1` 固定宽表，不接受任意 payload。SQLite 默认位于
`data/runtime/agent-events-v1.sqlite3`，只保存 `run_id`、时间、固定组件/状态/原因码、数值
摘要和 SHA-256 指纹；问题、检索式、步骤 ID、thread ID、chunk ID、证据正文、模型请求响应、
异常消息、绝对路径与密钥均不落库。事件写入是 best-effort，可观测性故障不会阻塞回答，也
不会令 Runtime 绕过原有关闭失败门禁。

## 扩展研究工具与风险矩阵

`agent.tooling` 将 19 项扩展能力拆为 catalog、contracts、local、content、analysis、
scholarly、workspace、service 和 LangChain adapter。生产 factory 默认构造 closable toolkit，
`ResearchAgentRuntime.execute_tool` 是统一执行入口；`build_langchain_tools` 在提供 toolkit 时
返回核心 2 项加扩展 19 项。当前可引用 ReAct 路径仍固定从 `search_corpus/get_evidence`
形成 `EvidenceRecord`，其他工具结果只能作为后续研究输入，不能直接伪装成引用证据。

| 风险 | 工具 | Runtime 边界 |
| --- | --- | --- |
| `local_read` | 相邻块、元数据、血缘、目录、比较、表格、图片、公式、claim 候选证据、可复现性 | 不访问任意路径；按 ID、论文、页码和数量限制 |
| `network_read` | 学术搜索、标识符解析、引用图、论文状态 | 固定官方 provider、10 秒超时、只发送查询/标识符 |
| `restricted_compute` | 算术、实验数据统计 | AST/算法白名单；禁止 eval、Python、文件和网络 |
| `write` | 笔记、报告、长期记忆变更 | 参数绑定的一次性审批；仅 `data/runtime`；拒绝路径逃逸和默认覆盖 |

`ExtendedToolPolicy` 可整体关闭网络、受限计算或写入风险类别。每次调用继续产生
`tool_started/tool_completed/tool_failed/runtime_intercepted` 结构化事件；未知工具、风险关闭、
超时和等待审批均关闭失败或返回明确的 `approval_required`，不会自动扩大权限。

## 动态工具路由与人工审批恢复

扩展工具使用独立的 `paper_research_dynamic_tools_v1` Graph，避免改变原有引用型 RAG Graph 的
终态不变量。Graph 从 `recall_memory` 开始，将命中的有效长期记忆单独放入 `memory_context`，再
交给 Router。Router 只能生成严格的 `ToolDecision(call_tool | finish)`；工具名必须属于 19 项目录，
参数必须先通过对应 Pydantic Schema。Runtime 记录已执行调用的规范化 SHA-256，相同工具与参数
不会被重复执行，整个循环受步数和总超时限制。

工具观察按用途隔离信任等级：正文血缘、相邻证据、表格/图片/公式与 claim 候选属于
`citation_evidence`；论文元数据和固定学术 API 返回属于 `research_context`；统计和算术属于
`computed_result`；写入结果属于 `side_effect`。该标签由冻结目录设置，不接受模型自行声明。

写工具第一次执行只创建与工具名、去除令牌后的参数哈希绑定的短期请求。Graph 随即通过
LangGraph `interrupt` 持久化暂停；Web 只展示工具名、用途、参数哈希与有效期。恢复时，拒绝或
过期直接终止，批准则生成一次性令牌并在同一 checkpoint thread 内执行；节点恢复前不会发生
文件或数据库副作用。动态 thread 使用 `dynamic::<conversation_id>` 命名空间，清空会话时与默认
Graph thread 一起删除。

Router 正常完成回答后进入 `propose_memory`。候选生成器先执行确定性的明确意图门禁：普通问答
直接返回 `none`，只有“记住、更新记忆、忘记”等明确请求才调用结构化输出模型。模型不能绕过
该节点直接修改记忆；新增、更新和删除统一复用上述审批暂停/恢复路径。长期记忆位于
`data/runtime/long-term-memory-v1.sqlite3`，记录包含作用域、内容哈希、版本、状态、替代关系、
来源 chunk ID 和可选过期时间；更新追加新版本，删除为软删除，读取只返回未过期的活动版本。
记忆召回始终是 `research_context`，不进入 observations，也不能满足引用要求。

## 产物血缘

每个派生产物必须能追踪到：

```text
corpus_version
source_pdf_sha256
parser_name + parser_version
chunk_schema_version + chunk_config_hash
embedding_model + embedding_revision
index_build_id
evaluation_dataset_version
code_commit
```

首版检索结果必须返回 `corpus_id`、`element_id`、`chunk_id`、`page`、检索分数和原文证据。

## 数据接入层次

V0 派生产物按以下层次组织：

```text
documents -> assets -> pages -> sections -> elements -> chunks
```

- `documents` 保存规范论文实体与默认证据版本。
- `assets` 绑定具体 PDF、来源和 SHA-256。
- `pages` 区分 PDF 索引、显示页码、原文和归一化文本。
- `sections` 保存标题路径和父子关系。
- `elements` 保存正文、表格、图片、公式和参考文献及其坐标。
- `chunks` 只保存检索单元，并通过元素位置区间回指原始证据。

同一输入和配置重复运行时，ID、记录数和输出哈希必须一致。
