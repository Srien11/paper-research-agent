# 数据与评测政策

## 仓库政策

以下内容禁止提交：

- `internal_research_only` PDF 及其可还原全文的解析文本、OCR、图片裁剪和索引。
- 原始或可再分发 PDF；源码仓库只保存来源、哈希和许可元数据。
- `.env`、API token、本地绝对路径、包含全文的 trace。
- FAISS、SQLite、embedding 缓存和实验运行目录。

即使远程仓库为 private，这些限制仍然生效。

## 私人研究模型处理边界

当前回答链路仅用于个人、非商业的 `private_research` 模式。已经通过版权映射校验的
`internal_research_only` 论文可以把少量检索命中片段临时发送给配置的百炼模型处理，但
必须同时满足：

- 不上传整篇 PDF、整篇解析文本或足以重建全文的连续片段。
- API Key 只从环境变量读取；请求体、响应体、上下文和证据正文不写日志或审计数据库。
- 最终 JSON 只保存回答、claims、最小引用元数据和调用统计，不保存证据正文或图片记录。
- 不提供公开导出模式；若未来对外发布，必须在调用模型前排除
  `internal_research_only`，并重新审查论文许可和平台数据条款。

## 短期记忆政策

- Web 编排层共享会话账本按服务端生成的 conversation ID 隔离，保存原用户问题、独立问题、
  路由、回答状态、有限助手摘要、来源 ID、Episode ID、采用历史 turn ID/相关度和时间戳。
- Conversation RAG 优先召回用户问题；助手摘要只辅助指代消解，不得作为 Paper RAG 的事实
  或引用来源。禁止把整段对话历史翻译后直接作为论文检索式。
- Turn Interpreter 每次只接收有界最近窗口、远距候选和 Episode 摘要；输出只能采用输入中的
  turn ID。确定性规则负责隔离、能力约束与输出校验，不以关键词未命中为由关闭历史上下文。
- 清空会话必须同时删除原始轮次和 Episode 索引；不同 conversation ID 之间不得召回。

- 只有显式提供 `session_id` 才启用；不同 session 不得互相读取。
- 只保存原用户问题、引用验证后的 claims、chunk ID、语料 ID、文本哈希和版权分类。
- 禁止保存证据正文、图片 JSON、完整 answer markdown、旧 `E<number>`、system prompt、
  provider 请求/响应或 API Key。
- 默认 24 小时逻辑过期，并在读写时删除到期行；这不等于 SSD 取证级安全擦除。每个
  session 的轮数受限，SQLite、WAL 和 SHM 文件均禁止提交。
- 记忆是对话连续性数据，不是论文证据。所有事实回答必须重新检索并引用当前证据。
- memory-aware 改写缓存及查询审计明文的期限不得长于记忆 TTL。

论文获取和使用仍必须符合原始来源许可；“个人、非商业”不自动覆盖明确禁止第三方云处理
的条款。

## 扩展研究工具数据边界

- Semantic Scholar/Crossref 工具只能发送当前用户明确提出的学术检索式、DOI、arXiv ID、
  Semantic Scholar ID 或论文标题；禁止发送本地证据正文、图片摘要、对话历史、长期记忆、
  本地路径或版权受限派生数据。
- 网络响应只投影书目元数据、摘要、官方链接、开放获取链接、引用关系和出版状态；Provider
  原始响应不得写日志、长期记忆或 Git。
- 算术与实验分析完全本地执行。实验分析只接受调用参数中的有界数值矩阵，不读取任意 CSV
  路径，不执行用户代码，也不把数据发送到网络。
- `save_research_note`、`export_research_report` 和长期记忆新增/删除必须经过一次性审批；产物
  只能位于 `data/runtime/research-notes`、`data/runtime/exports` 或本地长期记忆 SQLite，禁止
  提交。报告导出不自动改变 `internal_research_only` 的许可边界。
- 长期记忆只保存用户确认的偏好、项目背景和结论，并保留来源 chunk ID、更新时间和可选
  过期时间。它与短期记忆一样是低信任非证据数据；事实回答仍须重新取证。

## 私有 Web 可视化政策

- 公开个人站只允许展示项目名称、技术路线和聚合规模，不得提供匿名全量问答接口。
- 包含 `internal_research_only` 的 80 篇完整索引只能由站长认证后的私人研究台访问。
- Web 响应仅投影回答所需的标题、官方链接、页码、版权分类、稳定 ID 和截断证据摘录；
  禁止返回本地路径、PDF、图片文件、完整 figure JSON、系统提示词和 Provider 原始数据。
- Web 访问日志不得记录问题、答案或证据正文；查询与回答仍使用现有脱敏审计策略。
- 部署代码包与私有数据包分离。代码包可以进入 Git，chunks、FAISS、SQLite、论文清单
  派生物、模型缓存和环境文件只能通过受控通道进入服务器私有目录。
- 若未来开放匿名访问，必须在检索和生成之前使用独立的 redistributable-only 索引，并重新
  审查来源许可、API 平台条款、速率限制和滥用防护，不能只在输出阶段隐藏受限引用。

## 索引字段白名单

主检索基线只允许索引：

- PDF 派生正文、标题、章节和明确来源的图表转写。
- 论文标题、作者、年份、venue、DOI/arXiv ID 等书目事实。

禁止索引冻结清单中的：

- `challenge_question_ideas`
- `challenge_tags`
- `selection_reason`
- `paper_role`
- `topics`
- 含评测设计意图的 `version_note`

这些字段用于语料治理和评测设计，进入索引会造成答案提示泄漏。

## 数据集术语

`dataset_split=challenge` 表示困难论文集合，不等于评测问题的 `dev/test`
划分。评测问题另行创建、版本化和冻结。

标准证据的权威定位使用：

```text
paper_id + evidence_version_id + page + raw quote/span + span_hash
```

`chunk_id` 是特定切分配置下的派生映射，不能成为唯一标准答案。

## 解析门禁

现有冻结语料的解析检查抽查了每篇约五页。进入索引前必须：

- 对 2286 页逐页记录成功、失败和隔离状态。
- 保留原文与归一化文本，引用只回指原文 span。
- 将 OCR/VLM 派生内容标记为 generated，并记录模型和版本。
- 全量复核四篇特殊 PDF，并抽样人工核对至少十篇。
- 验证零 orphan chunk、零重复 ID 和零跨版权分区泄漏。

## 主 Agent 统一入口数据政策

- Conversation Store 是 turn、goal、plan、workspace 和 run 的唯一权威状态；LangGraph
  checkpoint 只负责恢复执行位置，不得覆盖或旁路原子提交门禁。
- `request_id`、`run_id`、`turn_id`、`task_id` 和 attachment ID 可以持久化；用户问题、
  论文证据正文、Provider 请求/响应、系统提示词、工具完整参数和密钥不得写入事件库。
- 附件和生成文件按 conversation ID 校验所有权。文件编辑必须创建新 attachment，不得
  静默覆盖原文件；跨会话读取、下载、状态查询和审批恢复一律关闭失败。
- 审批公开投影只允许工具名、用途、参数 SHA-256 和过期时间。批准、拒绝或过期后均不得
  复用；批准恢复不得重新执行 interpret、goal reconcile 或 plan。
- `primary` 与 `legacy` 共享现有数据边界。回滚不授权复制、导出或手工修改生产数据库。

## 主 Agent 发布评测政策

统一接口金标固定在 `evaluation/datasets/main-agent-interface-v1.jsonl`，覆盖普通聊天、
单/多论文、本地加动态混合研究、附件、文件编辑、审批批准/拒绝/过期、重复请求、
`required`/`disabled` 约束和提交拒绝。发布评分同时报告：

- route correctness（路由正确率）与 goal continuity（目标连续性）；
- artifact/citation preservation（产物与引用保留率）；
- approval resume correctness（审批恢复正确率）与重复副作用率；
- commit rejection（非法提交拒绝率）与 event contract validity（事件契约有效率）。

金标、自动测试和浏览器验收不得记录论文正文、用户原问题、密码、API Key 或完整工具参数。
发布报告只保存场景 ID、状态、计数、耗时、结果摘要、测试数量和代码提交号。真实浏览器必须
证明新页面只调用 `/agent/runs` 与统一审批接口，生成稳定 request ID，完成后清除待重试 ID，
并保持零控制台错误、零失败请求、零旧业务端点调用。
