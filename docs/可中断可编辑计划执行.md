# 可中断、可编辑的计划执行

## 目标

主 Agent 的计划执行采用“步骤结果是事实，计划是可修订视图”的模型。暂停、修改或恢复运行时，已经完成的步骤、产物引用、资源用量和调用次数都必须保留；调度器只选择尚未完成且依赖已满足的步骤。

## 状态与控制边界

运行控制状态独立持久化在 `main_agent_controls`，使用单调递增的 `revision` 做乐观并发控制。客户端提交控制命令时必须携带最近读取的版本；过期命令返回 `409`，不会覆盖其他控制操作。

- `running -> pause_requested -> paused`：暂停是协作式的，在当前原子步骤结束后的首个任务边界生效。
- `paused -> resuming -> running/completed`：继续使用同一 `request_id` 与 `run_id`，从已提交工作区恢复。
- 活动状态可进入 `cancel_requested -> cancelled`：只取消未完成步骤，已完成结果不回滚。
- `completed`、`cancelled`、`failed` 是终态，不接受继续或重复取消。
- 敏感工具的 `waiting_approval` 仍使用既有审批恢复通道，也可以直接取消整个运行。

进程退出、浏览器断线或重复请求不会清除控制状态。SQLite 与内存实现遵守相同契约。

## 计划编辑语义

计划只能在 `paused` 状态编辑。每次编辑必须携带 `expected_revision`（计划版本），成功后计划版本加一。

支持：

- 修改目标和验收标准；
- 修改未完成步骤的标题、目标、成功标准、执行原因和预算；
- 在不破坏依赖拓扑的前提下调整顺序；
- 跳过未完成且非运行中的步骤；
- 只把指定的失败步骤恢复为 `pending`；
- 查询每一步的执行原因、依赖、能力和成功标准。

完成步骤不可编辑、不可跳过、不可重试。它的 `status=completed`、`result_ref`、`attempt_count` 与资源用量在任何计划修订中保持不变。

## 单步预算

每个任务可独立设置：

- `max_seconds`：累计执行秒数；当前调用只使用剩余时长，超时只失败该步骤；
- `max_calls`：累计子任务调用次数；
- `max_cost_usd`：累计估算费用。

任务快照持久化 `elapsed_seconds`、`call_count` 和 `cost_usd`。调用前先检查累计预算，调用后原子累加本次用量。连接器尚未返回费用时，本次费用记为 `0`，不会伪造价格；接入提供方计费元数据后可通过 `ChildTaskResult.estimated_cost_usd` 纳入同一门禁。

## Owner API

所有接口都要求站长会话；修改接口还要求同源校验。

- `GET /paper-research/api/agent/runs/{request_id}/plan`：运行控制、目标、计划版本、步骤状态与预算快照。
- `POST /paper-research/api/agent/runs/{request_id}/control`：`pause`、`resume` 或 `cancel`，携带控制版本。
- `PATCH /paper-research/api/agent/runs/{request_id}/plan`：目标、验收标准、顺序、步骤编辑、跳过或失败步骤重试。
- `GET /paper-research/api/agent/runs/{request_id}/tasks/{task_id}/explanation`：查看“为什么执行这一步”。

前端的“计划执行”控制台在请求发出时立即出现，因此即使主请求仍在等待结果，也可以从另一个 HTTP 请求发出暂停或取消命令。计划尚未生成时会短轮询，生成后展示完整步骤与预算编辑器。

## 恢复不变量

发布门禁必须覆盖：

1. 第一步完成后暂停，工作区为 `[completed, pending]`；
2. 继续后总调用次数只增加一次，第一步不再次调用；
3. 取消后工作区为 `[completed, cancelled...]`；
4. 只重试失败步骤不会清除其他完成产物；
5. 过期控制版本和计划版本均返回冲突；
6. 时间预算超限只终止当前步骤并记录已用时；
7. SQLite 与内存仓储行为一致。
