# 单次问答的独立检索小批次

现有网页问答入口和 API 继续使用原来的权限、语料范围、来源策略和引用验证。
这项优化针对固定研究图中的非比较研究；普通 `auto` RAG 如果直接执行一次检索，不经过这项优化。
比较研究继续使用自己的并发策略，动态联网工具不在本次范围内。

## 执行规则

旧链路是逐次检索、逐次模型评估。开启小批次后，两个已经确定且独立的查询可以同时检索，
结果按原计划顺序汇合后只做一次模型评估。评估发现缺口后再生成追问；最终回答仍经过原有引用验证。

规划器只有在查询完整确定，且不依赖前一步结果、新实体或中间结论时，才允许将
`ResearchStep.independent_search` 明确标为 `true`。未填写该字段的旧计划默认 `false`。
运行时还检查以下边界：

- 每批最多两步，不超出冻结步数和工具调用预算；工具预算在调用启动前扣减。
- 查询与论文范围组合不能重复，结果顺序不随完成顺序变化。
- 按每条证据最多 2,000 字符估算新增证据容量；当前证据和新增证据可能超过共享的
  24,000 字符预算时，恢复单步执行，不改字符预算或截断策略。
- 新生成的追问、已经发生重规划的运行和连续无新增证据的运行继续单步执行。
- 批次完成后才写入观察和计数。失败或取消会取消并回收本批异步任务，不提交半批状态。
  已启动的本地只读线程任务可能继续完成，但其结果不提交。
- 无新增证据按批次计算；出现一次无新增证据后回退单步，继续使用原有停止门槛。

## 状态校验与恢复

`assessment_observation_counts` 记录每次评估实际看到的观察前缀。
研究图和 `ResearchAgentRuntime` 共用前缀验证规则。最终运行时仍逐条检查原始 chunk、正文哈希、
版权类别、工具调用账目、评估对应的证据前缀和终态一致性。

批量状态必须明确带有 `direct_batching_allowed=true`，每次新增观察最多两条；最终运行时还重新
验证该批步骤的独立性标记和证据容量。缺失批次信息的旧 checkpoint 保持逐步评估，不能猜测批次。
完成过批次的状态在配置恢复为单步后仍能通过原有安全边界校验；回滚不删除数据库或已完成任务。

## 配置与验证

`PRA_DIRECT_SEARCH_CONCURRENCY` 只接受整数 `1` 或 `2`，默认 `1`。
`1` 保持单步检索，`2` 允许通过上述检查的两步批次。
修改运行配置后必须重启现有本地服务才会生效。

切换到 `2` 前，需要同数据集、语料、模型、索引和上下文的配对质量验证，并确认样本实际命中了
两步批次。继续使用 `scripts/check_rag_regression.py`：成功率、状态准确率、claim F1、引用 F1、
必要证据组召回和论文召回不能下降；禁止及无支持 claim 率不能升高。缺少可比较的质量指标时不启用。

`scripts/smoke_web_runtime.py` 增加通用研究阶段耗时、检索批次数和评估次数，
避免把非比较评估错误理解为比较 Compiler。旧的兼容字段仍保留。
这些数据只含计数、耗时和安全状态，不新增问题、证据或答案明文日志。

## 研究连接的生命周期

研究运行时现在明确持有自己的异步 HTTP 连接。关闭一个运行时后，随后重建的运行时不会复用
已经关闭的连接；构造失败也会释放连接和 checkpoint 资源。
模型、超时和重试上限保持原配置。
